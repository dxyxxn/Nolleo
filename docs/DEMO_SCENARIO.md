# 길동무 — 3분 시연 대본

> Pleos Connect Emulator 2.1.0 기준. 실제 SDK 가 되는 부분(차량 상태·주행 규제·좌석·TTS·NaviHelper 이벤트)은 실제로,
> 에뮬레이터가 못 하는 부분(차량 이동에 따른 남은 시간 감소, 마이크 입력)은 **시뮬레이션 여정 + 대본 응답**으로 채운다.
> 화면 오른쪽(또는 별도 창)에 logcat 을 함께 띄우면 "SDK 이벤트 → 모드 전환"이 한눈에 보인다.

## 0. 녹화 전 준비 (영상 밖)

```bash
# 1) AVD 를 cold boot 로 켜고
adb devices
# 2) 설치 (처음 한 번)
adb install -r apk/Team-DonDoAYeon_길동무_release.apk
# 3) Virtual Console
adb forward tcp:8088 tcp:8088          # 브라우저: http://127.0.0.1:8088/
# 4) 로그 창 (선택)
adb logcat -v time -s Gildongmu/ModeArbiter:I Gildongmu/GameSession:I Gildongmu/Coordinator:I Gildongmu/NaviHelper:I Gildongmu/AaosCar:I
```

앱에서 (제목 **"길동무" 길게 누르기 → DEV 디버그 패널**):

| 설정 | 값 | 이유 |
|---|---|---|
| 데모 모드 | **켜짐** | 판당 6문제, 운전자 기준값이 없으면 1.5초로 시드 |
| 여정 | **시뮬** | 남은 시간이 실제로 줄어드는 흐름 (실제 1분 = 여정 30분) |
| 응답 입력 | **대본 normal** | 마이크 없이도 답이 들어옴 (TTS 는 실제 Pleos 음성) |
| 위치 | 자동 | 시뮬 여정 경로를 따라 지역이 바뀜 (서울 → 경기 → 충북 …) |

Virtual Console 은 **Motion > Gear Selection = P** 로 시작. 첫 실행이면 권한 2개(차량 속도·차량 위치)를 허용해 둔다.

## 1. 시연 (약 3분)

| # | 시간 | 화면/조작 | 보여 줄 것 (말할 것) | 사용 SDK |
|---|---|---|---|---|
| ① | 0:00–0:25 | **홈**. Virtual Console *Convenience > Seat Occupancy* 를 바꿔 "좌석 센서: 동승자 N명이 감지됐어요" 표시 → 적용. 목적지 **서울 → 부산**, 운전자 **아빠**, 동승자 **1명**, 게임 **번갈아** | 남은 시간에 맞춘 플랜 미리보기 **"4시간 10분 → 5판 (판당 약 10분)"** → **출발**. 주차 중이라 "정차 중 · 화면 게임"이 먼저 열림 | Vehicle(Seat), NaviHelper/시뮬 여정 |
| ② | 0:25–0:55 | Virtual Console **Gear = D** | 0.1초 안에 **음성 모드**로 전환(로그 `ModeArbiter: PARKED+DO → VOICE`), 화면은 3줄 이하 문제 + 정적 마이크 상태 + 버튼 1개("화면 조작 잠금"). TTS: "1번째 판! 지역 퀴즈… 지금은 서울특별시예요! 아빠 차례예요!" → 대본 응답 → "딩동댕!" **2문제** | AAOS Car API(기어·DO), TTS, STT 흐름 |
| ③ | 0:55–1:25 | 1판이 끝나면 쉬는 시간 화면("다음 판은 약 N분 뒤에 시작해요") → **"지금 시작"** (또는 기다리기) | 2판 **끝말잇기**: 길동무 → 아빠 → 조수석 순서, 두음법칙(예: '력'이나 '역') 안내, **3턴** | TTS, STT |
| ④ | 1:25–2:00 | 디버그 패널 → 응답 입력 **대본 sleepy** → Back → "지금 시작" | 운전자 응답이 2초→6초→무응답으로 느려짐 → **"잠깐 쉬어 갈까요? 반응이 조금 느려졌어요"** 카드 + TTS "아빠, 운전 오래 하셨죠? 다음 문제는 조금 쉬운 걸로 가 볼게요." 점수판에 "쉬운 문제 위주로 진행 중" (보조 기능 — 졸음을 단정하지 않음) | STT 응답 시간, TTS |
| ⑤ | 2:00–2:15 | 디버그 패널 → **TBT 분기점 300m** | 즉시 **"길 안내 후 이어서 할게요"**(TTS·STT 즉시 중단) → 8초 뒤 통과 → 1초 뒤 **같은 문제 다시** | NaviHelper(onTBTInfo) — 시뮬 TBT |
| ⑥ | 2:15–2:40 | Virtual Console **Gear = P** | 진행 중인 차례만 끝내고 "차가 멈췄네요. 이번 판은 여기까지…" → **화면 게임**(초성 퀴즈 / 그림 맞히기 준비 중) → 초성 퀴즈 한 문제 터치 → "정답! +10점" | AAOS Car API |
| ⑦ | 2:40–3:00 | Virtual Console **Gear = D** → 디버그 패널 **남은 5분으로** | 화면 게임이 즉시 닫히고 음성으로 복귀 → "곧 도착이에요! 오늘의 1등은 …" → **요약 화면**(점수·정답 수·지나온 지역 칩) | NaviHelper/시뮬 여정 |

### 팁
- ④ 를 한 판 안에 보여 주려면 홈에서 동승자를 **혼자**로 두면 된다(운전자 차례만 이어짐). 동승자가 있으면 1~2판 걸린다.
- ②~④ 에서 마이크로 직접 답하려면 에뮬레이터 *Extended Controls > Microphone > Virtual microphone uses host audio input* 을 켜고 응답 입력을 **마이크**로 둔다.
- 디버그 패널의 **정답 / 오답 / 무응답** 버튼으로 대본 대신 즉석에서 답을 넣을 수 있다(주행 규제 중에는 텍스트 입력만 막힘).
- 시연을 중간에 끊으려면 **일시정지 → 게임 끝내기**(정차 중에는 화면 게임 상단). 맞힌 문제가 있으면 "여기까지 했어요" 요약, 없으면 바로 홈으로 간다. 내비 경로는 그대로 남는다.

## 2. (선택) 실제 SDK 만으로 보여 주는 짧은 클립

| 클립 | 조작 | 기대 결과 |
|---|---|---|
| 실제 내비 경로 | 디버그 패널 여정 = **자동** → 홈에서 **근처 10분**(샘플 POI) 또는 **서울 → 부산** → 출발 | 순정 내비가 경로를 띄움, 로그 `onRouteStarted raw duration=14820 distance=378000`, 길동무로 돌아오면 "도착까지 4시간 7분" |
| 내비에서 잡은 목적지 | 길동무를 켠 채 내비에서 목적지 검색(최근: 부산역) → **안내 시작** → 길동무 홈 확인 | 1초 안에 **"내비 목적지: 부산역 · 남은 시간 4시간 2분"** 카드가 생기고 선택됨(로그 `navi route detected`) → 출발하면 경로 요청 없이 그 남은 시간으로 플랜 생성. 내비에서 **안내 종료** → 카드가 사라지고 프리셋으로 |
| 주행 규제 | 세션 없이 Gear = D | 홈이 "주행 중에는 여정 설정을 할 수 없어요"로 바뀜 (`NO_SETUP` 비트) |
| 3분할(내비와 나란히) | 길동무가 앱 영역 전체일 때 화면 오른쪽 끝 **⋮** 창 막대를 가운데로 끌기 | 길동무가 왼쪽 창으로 줄어든 직후 스스로 **맨 오른쪽**으로 이동 → Driving view \| 내비 \| 길동무 (로그 `Gildongmu/Window: 3분할 …`). 세로 1창 레이아웃도 잘리지 않음. 가운데 막대를 탭해 직접 자리를 바꾸면 그대로 둔다 |
| 백그라운드 | 하단 독의 내비 아이콘 → 다시 길동무 아이콘 | 발화가 끊겼으면 "잠시 멈췄어요 + 계속", 계속을 누르면 같은 문제부터 |

## 3. 녹화 전 체크리스트
- [ ] AVD cold boot, `adb devices` 에 emulator 표시
- [ ] `adb forward tcp:8088 tcp:8088` 후 Virtual Console 접속, 기어 P
- [ ] 권한 2개 허용(차량 속도·차량 위치)
- [ ] 디버그 패널: 데모 모드 켜짐 · 여정 시뮬 · 응답 입력 대본 normal
- [ ] (④ 전에) 응답 입력 대본 sleepy 로 바꿀 위치 확인
- [ ] 시스템 볼륨이 켜져 있는지(Pleos TTS 음성이 영상에 들어가야 함)
- [ ] 이전 세션이 남아 있으면 홈의 "새로 시작"
