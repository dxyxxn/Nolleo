> 날짜별 파일이 아니라 이 한 파일을 계속 갱신한다(2026-11-06 작성 시작, 마지막 갱신 2026-11-08). 11/7 까지는 `docs/state/2026-11-06_work-status.md` 였다.

- 브랜치: `main` — 프로토타입 작업 브랜치를 사용자가 main 으로 합쳐 `origin`(github.com/dxyxxn/Nolleo — 11/8 저장소 이름이 HMC-Contest 에서 바뀌어 로컬 원격 주소도 새 주소로 바꿈)에 push. 이때 히스토리가 다시 쓰여 아래 커밋 해시는 현재 main 기준이다. 11/8 검토 문서 기반 리팩토링(`refactor/review-fixes`, 1.21)은 같은 날 사용자 요청으로 main 에 합쳤다(fast-forward 라 해시 그대로). 같은 날 홈 목적지 개편(1.22)·출발 뒤 다시 앞으로(1.23)도 `feature/home-destinations` 에서 작업해 사용자 요청으로 main 에 합쳤다(fast-forward). 11/8 저녁 main 을 `origin` 에 push 했고, 합친 두 브랜치는 로컬에서 지웠다(원격에는 main 만 있음). 그 뒤 게임 선택 랜덤·정차 끝말잇기 말로 잇기·남은 초·글자 크기(1.24)와 그 후속(1.25·1.26)은 `feature/game-updates` 에서 작업해 11/8 밤 사용자 요청으로 main 에 합치고(fast-forward) push 한 뒤 브랜치를 지웠다.
- 기준 지시서: 처음 받은 프로토타입 구현 지시서(Claude Code 용)는 11/8 사용자 요청으로 저장소에서 지웠다(1.16). 이 문서의 옛 기록에 나오는 "지시서" 는 그 문서를 말한다 — 내용은 git 기록(`3d06bbc` 까지)에서 볼 수 있다. 코드 주석의 지시서 표기는 같은 날 정리했다(1.17).

- 졸음 기준값: 캘리브레이션 5개는 중앙값, 무응답(8초)은 캘리브레이션에서 제외, EMA 는 느리지 않은 응답으로만 갱신.
- 데모 모드: 판당 6문제, 운전자 기준값 없으면 1.5초 시드. sleepy 대본은 운전자 차례에만 적용(driverOnly). 데모 세션은 운전자 기준값을 저장하지 않는다(시연용 시드가 실제 기준값이 되지 않게 — 11/8, 1.21).
- **이어서 하기**(11/8 사용자 결정, 1.21): 시뮬 여정은 저장할 때의 남은 시간부터 이어 간다(꺼져 있던 동안은 흐르지 않은 것으로 봄). 쉬어 가기 진행(가는 중·쉬는 중)은 이어 가지 않고 처음 상태로 시작한다. 졸음 2단계 쿨다운·횟수, 끝말잇기 최장, 운전자 id 는 저장본 v2 에 넣었다. 시간 여정(목적지 없이)도 같은 규칙으로 이어 간다 — 저장본 v3 에 전체 시간·"목적지 없이" 여부(1.22).
- **홈 목적지 = 현재 경로 · 내비 최근 목적지 · 목적지 없이**(11/8 사용자 결정, 1.22): 고정 프리셋(서울 → 부산 등)은 홈에서 빼고 시연용 **시뮬 경로**로 디버그 패널에 옮겼다(여정=시뮬이면 홈 현재 경로 자리). 최근 목적지는 **출발을 누를 때** 길 안내를 걸고(고르기만 해서는 내비를 바꾸지 않음), **길 안내 중에는 숨긴다**(운전자 길 안내를 바꾸지 않게). 목적지 없이는 **30분 · 1시간 · 1시간 반 · 2시간** 네 칸.
- PARKED 판정: 기어를 알면 기어만 본다(에뮬레이터는 D 상태에서도 주차브레이크 텔테일이 켜질 수 있음).
- 졸음 케어 2단계(11/7, 사용자 결정 반영): **경로 정보가 있으면 경로 위 휴게소·졸음쉼터에서만 고른다**(가장 가까운 곳, 휴게소가 5 km 안쪽으로만 더 멀면 휴게소). **경유지(`addWaypoint`)는 넣지 않는다** — 좌표 경유지가 우회 경로를 만들었고, 경로 위라 필요 없다. 길 안내가 없을 때만 공공데이터 졸음쉼터 표(근사, "A기점 + B종점" 은 A → B 차로로 해석). 도착은 근처에서 서거나 주차해야(지나가는 것과 구별). 도착 안내 뒤에는 다시 출발할 때까지 문제를 내지 않는다(`PauseReason.REST_AREA`). 질문 문구는 "졸음"을 단정하지 않고 "반응이 계속 느려졌어요".
- 디버그 패널은 release 에도 그대로 둔다(11/7 사용자 결정 — 시연·심사용, 11/8 다시 물어 "지금처럼 두자"). 앱 마켓 제출본에서는 빼거나 차량 칸(시뮬 전환·시뮬 DO 끔 — 주행 규제 우회 가능)을 숨길 것(빌드 스위치 하나로 나누는 방법을 제안해 둠).

- **APK 파일 이름 = `apk/돈도아연_놀레오_release.apk`, 팀명 = `돈도아연`**(영문으로 적을 때 DonDoAYeon) — 11/8 사용자 최종 결정. 같은 날 오전에 `DonDoAYeon_Nolleo.apk` · `돈도아연(DonDoAYeon)` 으로 바꿨다가 오후에 확정(1.15).
- **정차 중 화면 게임 = 사자성어 · 지역 퀴즈 · 끝말잇기**(11/8 사용자 요청): 지역 퀴즈·끝말잇기는 주행 중 음성 판과 **따로 노는 터치판**(점수·진행이 이어지지 않음). 틀린 그림 찾기(그림 맞히기에서 바꿈)·노래방은 "준비 중" 카드만. 게임 화면은 창 크기와 상관없이 가운데 맞춘 위아래 배치. 세 게임 모두 사자성어와 같은 소리 규칙(`ScreenQuizController`). → 11/8 저녁 끝말잇기는 보기 고르기 대신 **말로 잇기**로 바꿨다(아래, 1.24).
- 누르는 표시는 Material 물결 대신 **누르는 동안만 어둡게**(`Modifier.pressable`) — 물결은 회색이 천천히 빠져 느려 보였다(11/8 사용자 피드백). 주행 중 애니메이션 금지와도 맞는다.
- **끝말잇기 사전 = 국립국어원 사전 기반 두 파일**(11/8 사용자 요청 — 작업 지시 파일은 작업 뒤 지움): 사람 답은 검증용(표준국어대사전·한국어기초사전 명사 + 팀 검토 일상 복합어 184어), 앱 차례·정차 보기는 출제용(한국어기초사전 초급·중급 + 사전 등재 팀 목록)에서만. 두음법칙은 ㄹ·ㄴ 초성 양방향(판정·막다른 음절 계산이 같은 함수), 앱이 말하는 낱말·안내는 표준 방향 먼저. 난이도 상한 1 → 초급만, 2 → 초급·중급·팀목록, 3 → 전부(후보가 없으면 넓힘 — 11/8 부터 첫 낱말도 같은 규칙, 1.21). 사전 파일은 고치지 않고 금칙어 목록 `words_blocklist.txt` 로 거른다. 판단 내용은 아래 1.19. **요약의 "끝말잇기 최장"은 다른 말로 다시 시작한 전후를 합친 한 판의 낱말 수**(11/8 사용자 결정).
- **게임 선택에 랜덤**(11/8 사용자 요청, 1.24): 판마다 지역 퀴즈·끝말잇기 중 무작위, 같은 게임이 세 판 넘게 이어지지 않는다(앞 두 판이 같으면 셋째 판은 다른 게임). 순서는 씨앗(`gameSeed`) 하나로 정해 미리보기·판 다시 짜기·보너스 판·이어서 하기가 모두 같은 순서를 쓴다. 앱을 켤 때와 **랜덤**을 누를 때마다 다시 섞는다. **미리보기에는 순서를 보이지 않는다** — 무엇이 나올지 모르고 시작한다(11/8 사용자 요청, 1.25). 판이 시작될 때 발화·칩으로 알린다.
- **정차 중 끝말잇기 = 말로 잇기**(11/8 사용자 요청, 1.24): 음성 판과 같은 규칙(`WordChainGame` 그대로)으로 놀레오 → 운전자 → 동승자. 판 길이는 없고, 사람 수만큼(적어도 2번) 잇달아 대답이 없으면 끝낸다(마이크를 계속 열어 두지 않게). 정차 중이라 난이도 상한은 두지 않는다. 판이 도는 동안(말하기·듣기) 포커스를 계속 잡는다 — 차례마다 반납하면 다른 소리가 오르내리므로. 멈추면(목록·출발·포커스 손실 등) 같은 차례부터 이어 하고, 저절로 다시 하지 않는다. 점수는 다른 화면 게임처럼 세션 동안만. 화면 게임 공통 동작은 `ScreenGameController` 로 묶었다.
- **끝말잇기 남은 초**(11/8 사용자 요청, 1.24): 사람 차례의 첫 말 기다림(8초) 동안만 보이고 말을 시작하면 사라진다. 숫자만 1초마다 바뀐다(애니메이션 없음). 3초 이하는 빨강 — "듣는 중" 표시의 일부로 보고 상태색을 썼다. 지역 퀴즈에는 띄우지 않는다(요청이 끝말잇기). 정차 끝말잇기도 같은 표시.
- **주행 중 끝말잇기 낱말 줄**(11/8 사용자 요청, 1.25): 정차 중 끝말잇기와 같은 모양(공통 `WordChainRow`)으로 문제 카드 맨 위에. 화면 글은 무엇으로 시작할지만 남겼다(낱말을 되풀이하지 않게). 줄은 다음 차례 글과 같은 때 바뀐다 — 칭찬하는 동안 줄과 "무엇으로 시작" 글이 어긋나지 않게. 창이 좁으면 앞 낱말부터 빼서 한 줄에(넘김·잘림 없음). 글자 수 제한 규제(LIMIT_STRING_LENGTH)면 줄 없이 1줄 요약.
- **글자 크기**(11/8 사용자 요청 두 번): 처음 "아주 살짝만" — 14개 스타일을 1~4sp(가장 작은 19sp, 주행 본문 30sp). 이어 "더 키워 보자, 특히 홈"(1.25) — 다시 2~8sp(가장 작은 21sp, 주행 본문 33sp), 홈은 목적지 목록·설정 줄·선택 막대·미리보기·안내 줄을 한 단계 큰 스타일로. 좁은 창(3분할)에서 선택 막대 4칸 글이 잘리지 않는 선에서 멈췄다. 그 뒤 "주요 글씨는 적당, 서브 글씨는 너무 크다"(1.26) — 목록 줄 설명·오른쪽 값, 판 구성·쉬는 시간 줄, 안내 줄, 좌석 센서 글은 키우기 전 스타일로 되돌렸다(스타일 자체가 2sp 커져 예전보다 2sp 큼).
- **구분선**(11/8 사용자 선택, 1.26): "전체적으로 옅은 느낌" → 흰 카드에 바탕보다 살짝 짙은 1dp 테두리(`edge` — 낮 #D9DCE1, 밤은 카드보다 살짝 밝은 #2C3138), 가는 줄(`line`) 잉크 10% → 16%, 선택 막대의 고른 칸에 1dp 테두리. 지금 모습과 나란히 찍은 비교 사진(홈 낮·밤, 정차 게임 목록, 주행 음성 화면)을 보여 주고 "반영(사진 정도)"을 골랐다.
- **음성 파형은 하지 않는다**(11/8 사용자 결정, 1.26): TTS·STT 의 `onUpdatedRms` 로 만들 수는 있지만(1.25 답변) 주행 중 움직이는 그림 금지·CPU 기준 때문에 이득이 적다. 마이크 표시는 정적 3종 그대로.
- **시연 영상은 장면별로 찍어 편집한다**(11/8 사용자 결정, 1.28): 3분을 이어 찍지 않는다. 졸음 케어는 1단계 → 2단계가 저절로 걸리는 대로 찍고(대본 sleepy · 혼자 · 쉬지 않고) 기다리는 구간을 잘라 낸다. 최근 목적지 → 놀레오 다시 앞으로, 주행 중 끝말잇기(낱말 줄·남은 초)도 장면으로 넣었다. 디버그 패널 장면은 잘라 내고, 시뮬 여정·대본 응답은 자막으로 밝힌다.
- **문서 동기화 규칙**(11/7 사용자 요청): 작업을 마칠 때마다 관련 md 를 같은 작업 안에서 고친다. 어떤 변경을 어느 파일에 적는지는 `CLAUDE.md` "Keep the md docs in sync" 표(README·FEATURE_GUIDE·DEMO_SCENARIO·WORK_STATUS·PHASE2_NOTES·CONTENT_SOURCES·docs/README·CLAUDE.md)를 따른다. 커밋은 사용자가 요청할 때만, 커밋 해시는 뒤따르는 `docs:` 커밋으로 이 문서에 채운다.

### 1.5 문서·자료와 실제가 달랐던 점 (기획서/문서 수정 참고)

- `requestRoute` 를 호출하면 순정 내비가 같은 창 앞으로 나온다. 장거리 프리셋은 샘플에 POI ID 가 없어 **빈 poiId + 좌표·주소**로 요청했고 정상 수락됨.
- 경로가 없을 때도 `onDestinationInfo(remainTime=0, remainDistance=0)` 가 온다 → 무효 값으로 처리. 새 경로를 요청해 내비가 이전 경로를 취소한 직후에는 `onDrivingInfo` 도 0/0 으로 온다 → 같은 규칙으로 무시(11/7, 아래 1.10).
- 에뮬레이터 순정 내비는 고속도로 경로의 TBT 목록에 휴게소(`TURN_ENTER_SERVICEAREA`)·졸음쉼터(`TURN_RESTAREA`)를 경로 순서대로 넣어 준다. API 레퍼런스는 `TBTInfo.distance` 를 "Distance to the upcoming turn"이라고만 적었지만 실제로는 **앞 항목부터의 구간 거리**다(14000 → 9300 → … 처럼 순서대로 늘지 않고, 더하면 실제 거리와 맞음). `TURN_ENTER_SERVICEAREA` 에는 "하이패스센터"도 있다. 목록은 50여 항목까지. 경로가 없을 때(재탐색 중 등)는 빈 목록이 온다.
- `addWaypoint` 를 부르면 내비가 경로를 취소 → 재탐색(`onRouteCancelled` → FREE_DRIVE → `onWaypointChanged` → ROUTE_DRIVE)하고 앞으로 나온다. POI ID 없이 좌표만 주면 고속도로 시설을 근처 일반 도로에 붙인다(오산졸음쉼터 좌표 → 오산IC 로 나가 시내 "경유" 지점을 찍고 다시 진입).
- 에뮬레이터 내비는 서울(판교) → 부산역을 경부선이 아니라 영동선 → 중부내륙선 → 대구 → 청도로 안내한다(378 km, 약 4시간 10분).
- 공공데이터포털 15045551 "고속도로 출입시설 위치정보(LOD)"는 설명에 휴게소·졸음쉼터가 있다고 하지만 실제 파일에는 IC·JCT 407곳뿐이다.
- Pleos TTS SDK 는 발화 텍스트를 자체 logcat(`[GAAS][SDK]OnDeviceStreamTts doSpeak text=…`, D 레벨)에 남긴다 — 앱이 막을 수 없는 SDK 동작(앱 로그는 PII 규칙을 지킴).
- AAOS 런타임 권한 대화상자에서 `CAR_SPEED` 는 "위치" 그룹으로 표시되고, `FUSED_LOCATION` 은 라벨이 없어 "알 수 없는 작업"으로 보인다(플랫폼 측 표기).
- HOME 키는 이 에뮬레이터에서 앱 창을 가리지 않는다(전용 홈 패널) → 백그라운드 검증은 다른 앱을 같은 창에 띄워서 했다. `adb shell am kill com.nolleo.app` 도 화면에 보이는 앱이라 프로세스를 끝내지 않았다 → 이어서 하기 시험은 다른 앱으로 덮은 뒤 `am force-stop`(11/8).
- 앱은 Pleos 창을 나누거나 옮길 수 없다(11/8 에뮬레이터 시험, 1.23): `setRequestedOrientation(PORTRAIT)` 는 창을 나누지 않고 양옆에 검은 띠(레터박스 — 플랫폼 금지 사항)만 생기고, `ActivityOptions.setLaunchBounds`(왼쪽 절반)로 내비를 띄워도 앱 영역 전체를 덮는다(11/6 의 `FLAG_ACTIVITY_LAUNCH_ADJACENT` 무시와 같음). 창은 모두 `multi-window` 작업이고 경계는 시스템이 정한다.
- 이미 3분할(Driving view | 내비 | 놀레오)이면 `requestRoute` 를 해도 내비가 자기 창에서 길 안내를 시작하고 놀레오는 그대로 보인다(백그라운드 전환 없음). 놀레오가 앱 영역 전체일 때만 내비가 전체를 덮는다(내비는 SYSTEM_ALERT_WINDOW 권한으로 스스로 앞에 나옴 — 로그 `BAL_ALLOW_SAW_PERMISSION`).

- NaviHelper `requestTrip` 은 길 안내를 시작하지 않고 예상 시간만 `onTripInfo` 로 준다. 그런데 `onTripInfo`·`onRecentDestinationInfo` 는 **어느 앱이 물었든 모든 연결 앱에 온다**(요청 번호 없음 — 다른 앱의 요청에 대한 답도 받음). `TripInfo.summary.routePoints` 의 마지막 항목이 목적지라 그 좌표로 어느 곳의 답인지 맞춘다. 최근 목적지의 `poiSubId` 는 null 로 오는데 `RouteInfo.poiSubId` 는 null 을 받지 않아 "0" 을 넣는다. 등록 안 된 집·회사 즐겨찾기(`getBookmarkInfo`)는 빈 이름·0 좌표로 온다(11/8).
- DEV_GUIDE §6.5 는 글꼴을 Asta Sans 로만 적었는데, 에뮬레이터의 `/product/etc/fonts_customization.xml` 은 `sans-serif` 를 Asta Sans 로 덮으면서 **굵기 500 을 Regular, 600 을 Bold, 700 을 ExtraBold** 파일에 연결한다(Medium 파일은 `pretendard` 라는 이름의 별도 글꼴 묶음에만 연결). 그래서 `FontWeight.Medium` 은 Regular 로 보인다 → 400·600 두 굵기만 쓴다(11/7).
- Material3 기본 색 역할(secondaryContainer 등)을 채우지 않으면 슬라이더 빈 트랙 같은 곳에 기본 보라색이 나온다 → 테마에서 색 역할 전부를 우리 색으로 지정(11/7).
- 에뮬레이터의 Pleos Vehicle SDK 좌석 착좌(Seat Occupancy)는 동승석 4곳(`ROW_1_RIGHT`·`ROW_2_LEFT`·`ROW_2_CENTER`·`ROW_2_RIGHT`)을 처음부터 모두 착좌로 보낸다. Virtual Console 의 Seat Occupancy 를 바꿔도(화면·HTTP API `PUT /vehicle/seat?kind=occupied…` 모두) 앱이 받는 값은 그대로였다 → 홈이 늘 "좌석 센서가 동승자 3명을 감지했어요"(앱이 고를 수 있는 최대 3명으로 줄임)를 띄운다. 앱이 값을 정해 둔 것이 아니다. 실차에서 실제 착좌가 반영되는지는 확인 못 함(11/8).
- 에뮬레이터 화면 밀도는 160dpi(`adb shell wm density`)라 1dp = 1px 이다 — 2560px 화면에서 sp 숫자가 그대로 픽셀이어서 같은 sp 라도 휴대폰보다 작게 보인다. 글자를 두 번 키운 까닭(1.24·1.25). 실차 화면 밀도는 확인 못 함.
- Pleos TextToSpeech·SpeechToText SDK 리스너에는 소리 크기 콜백 `onUpdatedRms(rms: Double)`(API 레퍼런스)이 있다. 지금은 쓰지 않는다(빈 구현) — 음성 파형은 하지 않기로 했다(1.26). 값의 범위·호출 간격은 확인 못 함(1.25 답변).
- 앱을 다시 설치해 아이콘을 바꿔도 하단 독(GNB)은 한동안 예전 아이콘을 보여 준다. 야간/주간을 한 번 바꾸자 새 아이콘으로 바뀌었다(런처 캐시, 11/7).

### 1.6 사용자 피드백 반영 (11/6)
피드백: ① 일시정지하거나 멈췄을 때 홈으로 돌아가는 "닫기"가 없다 ② 쉬는 시간 화면의 "남은 시간이 3시간 N분일 때 다음 판을 시작해요"가 "3시간 뒤에 시작"으로 읽힌다(실제 뜻은 "도착까지 남은 시간이 3시간 N분이 되는 시점").

| 변경 | 내용 |
|---|---|
| 게임 끝내기 | 음성 화면 하단: 일시정지·쉬는 시간·출발 대기·모든 판 완료 때 "게임 끝내기"를 기존 버튼(계속/지금 시작/한 판 더) 옆에 표시. 문제를 내고 듣는 중에는 "일시정지" 하나만(주행 중 터치 1개 원칙). 정차 중 화면 게임: 상단에 항상 |
| 끝낸 뒤 | TTS·STT 즉시 중단, 오디오 포커스 반납, 저장된 진행 상태 삭제, 내비 경로는 유지. 맞힌 문제나 마친 판이 있으면 요약("여기까지 했어요" — 11/7 전에는 앱 이름을 붙인 제목) → 처음으로, 없으면 바로 홈 (`GameCoordinator.endSession`, `SessionSummary.endedByUser`) |

### 1.7 사용자 피드백 반영 ② (11/6) — 내비 목적지 실시간 반영 · 3분할 배치
피드백: ① 놀레오를 켠 뒤 내비에서 길 찾기를 시작하면 홈에 "내비 목적지" 버튼이 생기지 않는다 ② 길 안내 중이면 내비도 보여야 하지 않나(3분할) ③ 3분할일 때 게임을 맨 오른쪽에 배치.

| 항목 | 원인·확인 | 변경 |
|---|---|---|
| ① 내비 목적지 카드 | 내비 앱에서 직접 시작한 길 안내는 `onRouteStarted`·`onNavigationStatus(ROUTE_DRIVE)` 만 오고 `onRoutingCompleted`·`onDestinationInfo` 는 오지 않음(로그 확인). 카드는 `onDestinationInfo`(조회해야만 옴)에서만 만들어지고 있었다 | `onRouteStarted` 에서 바로 카드 생성 + `getDestinationInfo` 재조회, `ROUTE_DRIVE` 수신 시 재조회, `onRouteCancelled`·`onDestinationArrived`·FREE_DRIVE 에서 카드 제거. 앱이 다시 보일 때 즉시 재조회, 길 안내 중(앱이 보이거나 실제 내비 여정으로 게임 중)에는 30초마다 재조회(`TripRepository.shouldPollNavi`) — 실제 내비 여정의 남은 시간이 멈춰 있던 문제도 함께 해결. 홈은 새 길 안내를 자동 선택, 안내가 끝나면 프리셋으로(`HomeState.withNaviRoute`) |
| ② 내비 함께 보기 | Pleos 화면 = Driving view(고정) + 앱 창 최대 2개. 창 위치·크기는 사용자가 정한다(§5.4·§6.3). `FLAG_ACTIVITY_LAUNCH_ADJACENT` 는 무시되고 내비가 앱 영역 전체를 덮음(확인) → 앱이 3분할을 만들 수는 없다 | 3분할은 사용자가 창 막대로 만들고, 놀레오는 세로 1창 레이아웃으로 그대로 동작(1차 때 확인한 그 테스트). 내비가 가려져 있을 때도 Driving view 에 TBT(회전 방향·거리)가 표시됨 |
| ③ 게임 맨 오른쪽 | 새로 앞에 나온 앱은 primary(운전석 쪽, 왼쪽) 창으로 가고 다른 앱은 오른쪽으로 밀린다(확인). NaviHelper `requestNavigationScreen(Foreground)` 는 내비가 이미 보이면 다시 실행되지 않아 효과 없음(확인) | 놀레오가 운전석 쪽 창에 "새로" 들어오면(창이 줄어듦·처음 보임·다시 앞으로 나옴) 기본 지도 앱(`ACTION_MAIN` + `CATEGORY_APP_MAPS`, 패키지 하드코딩 없음)을 실행 → Driving view \| 내비 \| 놀레오. 같은 크기로 자리만 바뀐 경우(사용자가 창 막대 탭)는 존중. 판단은 `WindowPlacement`(순수 함수), 실행은 `MainActivity` |

확인(release APK, 에뮬레이터): 놀레오를 켠 채 내비에서 안내 시작 → 7 ms 안에 `navi route detected` + 카드 선택("내비 목적지: 부산역 · 남은 시간 4시간 2분", 플랜 "4시간 2분 → 5판"), 안내 종료 → 카드 제거·프리셋 복귀, 30초 주기 재조회 로그 확인. 창 막대를 끌어 3분할 → 놀레오가 [853–1694] → [1718–2559]로 이동하는 동안 놀레오 생명주기 이벤트 없음(게임 멈춤 없음), 가운데 막대 탭으로 사용자가 바꾼 위치는 유지. 퍼미션 추가 없음(`NAVI_CUSTOM_MAP` 은 시험 후 제거). 테스트 115개(+13).

### 1.9 사용자 결정 반영 (11/7) — 판 간격 선택 · 화면에서 사라지면 일시정지 유지
결정: 판 간격은 "처음 화면에서 고르는 방식", 내비가 앱 영역 전체를 덮을 때는 "지금처럼 일시정지".

| 항목 | 내용 |
|---|---|
| 판 간격 선택 | 홈에 "얼마나 자주 할까요?"(11/7 디자인 개편 뒤 제목 `판 간격`) — **여유 있게**(기본, 약 45분마다) · **자주**(약 20분마다) · **쉬지 않고**(판 사이 2분). 4시간 10분 기준 5판(쉬는 시간 약 39분) / 12판(약 10분) / 20판(약 2분). 미리보기에 "판 사이 약 N분 쉬어요" 추가 |
| 구현 | `RoundPacing`(판 시작 간격 목표값) → `SessionPlanner.plan(…, pacing)`. 판 길이는 간격 안에서 여유 1/4·자주 1/2·쉬지 않고 "간격 − 2분"(모두 6~10분 제한), 최소 휴지 2분·도착 5분 전 종료 규칙은 그대로. 간격은 `SessionPlan.pacing` 에 담겨 남은 시간이 바뀌어 다시 짤 때(`replanRemaining`)와 이어 하기 저장본(`SnapshotCodec`, 이전 저장본은 여유 있게로 읽음)에도 유지. 마지막으로 출발한 간격은 설정(`AppSettings.lastPacing`)에 저장 |
| 일시정지 유지 | 놀레오가 화면에서 사라지면(onStop) 지금처럼 즉시 멈추고 포커스 반납·상태 저장, 다시 보이면 "계속"으로 같은 문제부터. 백그라운드 음성 진행(포그라운드 서비스)은 하지 않기로 결정 |

확인(release APK, 에뮬레이터): 홈 기본 "여유 있게" → "4시간 10분 → 5판 · 판 사이 약 39분 쉬어요", "쉬지 않고" → "20판 · 판 사이 약 2분 쉬어요"로 바뀌고 출발 시 `session start → … 20판`. 시험 뒤 간격을 "여유 있게"로 되돌려 둠. 테스트 120개(+4: 간격 3종·재계산 시 간격 유지·판 1개일 때 휴지 없음·옛 저장본 호환).

### 1.18 사용량 다시 재기 · 콘텐츠 검수 상태 정정 · 녹화 확인 (11/8)
요청: "① 콘텐츠는 아직 검수 안 했어. 검수한 건 사자성어뿐이야 ② (끝말잇기 사전 개수가) 어긋난다는 게 뭐야? ③ 사용량 다시 확인해 봐."

**사용량** — release APK(`apk/돈도아연_놀레오_release.apk`, `debuggable` 아님)를 에뮬레이터(4코어)에서 실제로 쓰면서 쟀다. CPU 는 앱 프로세스의 `/proc/<pid>/stat` CPU 시간(utime+stime)을 5초마다 읽어 평균과 5초 구간 최댓값을 냈고, 메모리는 `dumpsys meminfo` 의 TOTAL PSS 다. CPU % 는 **기기 전체(4코어) = 100%** 기준이고, 괄호 안은 코어 하나 = 100% 기준이다.

| 상황 | 시간 | CPU 평균 | CPU 최대(5초) | 메모리 PSS |
|---|---|---|---|---|
| 첫 실행(`am start -W`, 프로세스 새로 시작) | — | — | — | — · TotalTime **0.91초** |
| 홈 대기 | 30초 | 0.07% (0.27%) | 0.20% (0.80%) | 43.8 MB |

- 확인 못 함: 실차(에뮬레이터는 호스트 PC 성능을 따름), 마이크 응답(STT)을 켠 상태 — 이번에는 대본 응답이라 STT 인식은 돌지 않았다(STT 도 Pleos 서비스 쪽에서 돈다).

**콘텐츠 검수 상태 정정** — 사람 검수를 마친 콘텐츠는 **사자성어(`quiz_idioms.json`)뿐**이다. 지역 퀴즈 170·일반 48문항과 끝말잇기 사전은 아직 사람 검수 전(AI 작성 그대로)이다. 전에 CONTENT_SOURCES 에 "개발 중 170개 지역 문항을 한 번 훑어 확인했다"고 적었던 것은 틀린 기록이라 고쳤다.

**시연 영상 녹화 가능 여부(같은 날 사용자 질문 "직접 찍을 수 있는지만 확인")** — 둘 다 된다.

- 시연 영상(11/15)은 지금 main 의 APK 로 찍는다 — 11/8 밤 시나리오를 장면별 촬영·편집으로 다시 썼다(1.28). 클립 E(졸음 케어)는 출발 전에 대본 sleepy·혼자·쉬지 않고로 맞춰야 1·2단계가 저절로 걸린다
- 실차에서 내비가 주행 중 `onTBTInfo`·`onDrivingInfo` 를 스스로 보내는지 확인 (에뮬레이터는 차가 움직이지 않아 확인 불가). 남은 시간은 30초 재조회로 보완했지만 TBT 자동 일시정지는 push 에 의존
- 3분할 자동 배치는 좌핸들·Connect-S 배치(Driving view 왼쪽, 앱 창 1:1)에서만 확인. 우핸들·Connect-W(2:1, 조수석 App library) 에서 동작 확인 필요
- 실제 Suspend(IGN OFF) 진입 시 동작 확인(현재는 onStop 경로로 처리)
- `distractionOptimized` 선언이 Pleos App Market 심사에서 허용되는지 확인(앱 카테고리·DO 승인 절차)
- AAOS `CAR_SPEED` 를 거부했을 때(기어만으로 동작) UI 문구 점검
- STT 동음이의 오인식 사례 수집 후 AnswerMatcher 보정, 실제 마이크로 끝말잇기 낱말(예: 주행거리)이 인식되는지 확인 — 사전 쪽 비표제어 정리는 11/8 사전 교체로 끝남(1.19). 11/8 저녁부터 정차 끝말잇기도 말로 하므로(1.24) 같은 확인이 정차 중에도 필요하고, 정차 끝말잇기의 통화·Gleo 포커스 손실(즉시 멈춤·자동 재개 없음)도 코드만 있다
- lint 경고 17건: 의존성 최신 버전 안내 13건(GradleDependency 8·NewerVersionAvailable 4·AndroidGradlePluginVersion 1 — Kotlin 2.2.10 호환을 위해 의도적으로 고정), Pleos SDK 의존성 JNA 의 16KB 정렬 3건(SDK 측 업데이트 필요), 라이브러리 lint 검사 건너뜀 1건(ObsoleteLintCustomCheck)
- Android TTS 폴백은 이 에뮬레이터에 한국어 엔진이 없어 실행 검증 못 함
- 계측 테스트(`connectedDebugAndroidTest`)는 작성하지 않음 — 2차 전 Compose UI 테스트 추가 고려
- 졸음 케어 2단계 실차 검증·보완 — `PHASE2_NOTES.md` §1
- 시뮬 여정은 쉬어 가기를 묻는 동안 멈춘다(30배속 보정). 실제 내비 여정에는 해당 없음
- 세로 1창에서 홈·음성·게임 목록·게임 화면 배치(위아래 + 스크롤) 확인 — `wm size` 로는 Pleos 화면이 다시 배치되지 않아 에뮬레이터에서 못 봄
- App Market 제출본에서는 디버그 패널을 빼거나 차량 칸(시뮬 전환·시뮬 DO 끔 — 주행 규제 우회 가능)을 숨길 것(1.4)

## 3. 다시 시작할 때 참고
- 빌드/검사: `./gradlew lintDebug testDebugUnitTest assembleRelease` → `apk/` 에 복사 (`app/build/outputs/apk/release/app-release.apk` → `apk/돈도아연_놀레오_release.apk`)
- 에뮬레이터 차량 조작 자동화: `adb forward tcp:8088 tcp:8088` 후
  `curl -X POST "http://127.0.0.1:8088/browser/session?client=cli"` (하트비트, 3초 유효) → `curl -X PUT "http://127.0.0.1:8088/vehicle/gear?gear=Drive"`
- 로그: 태그 목록과 대표 문구는 `docs/FEATURE_GUIDE.md` §12, 필터 명령은 §0.5. debug 빌드의 `AppLog.sensitive` 값(예: `TBT.restStops=`)은 DEBUG 레벨이라 `Nolleo/NaviHelper:D` 처럼 D 로 걸어야 보인다
- 졸음 케어 2단계 시험: 디버그 패널 여정 시뮬 · 시뮬 경로 서울 → 전주 → 출발 → D → 디버그 패널 "2단계 시험" → 대본 응답이 "네" → 기흥휴게소(편의시설) → 시뮬이 닿으면 도착 → 기어 P → D. 실제 내비 + 근접 알림은 `geo fix 127.10 37.40` → 여정 자동 → 홈 최근 목적지 부산역 → 용인졸음쉼터 → `adb emu geo fix 127.138727 37.288616`.
- 자료 다시 만들기: 졸음쉼터 `node tools/convert_rest_areas.js <CSV> app/src/main/assets/content/rest_areas.json`, 휴게소 `node tools/convert_service_areas.js <serviceAreaAmenities.json> <가족사랑화장실.csv> app/src/main/assets/content/service_areas.json`. 시뮬 경로 목록을 다시 받으려면 debug 빌드로 실제 내비 출발 후 logcat `TBT.restStops=`
- 기능별 확인 절차 전체: `docs/FEATURE_GUIDE.md`
- SDK 사용법이 헷갈리면 `pleos-example/` 샘플(Vehicle `VehicleClient.kt`, Navi `NaviHelperViewModel.kt`, FusedLocation `FusedLocationClient.kt`)과 대조
- 에뮬레이터 위치: `adb emu geo fix <경도> <위도>` (예: 서울 시청 `126.9780 37.5665`) → FusedLocation 지역 판정
- 코드 지도: README §5 아키텍처, 주요 진입점 `app/GameCoordinator.kt`, `domain/engine/GameSession.kt`, `domain/engine/ModeArbiter.kt`
