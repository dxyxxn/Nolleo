## 0. 먼저 준비하기

### 0.1 에뮬레이터와 설치
```bash
# AVD: Pleos_Connect_v2.1.0 (Android 14, 2560×1440) — 반드시 Cold boot (Quick boot 면 VHAL 이 없음)
adb devices
adb install -r apk/돈도아연_놀레오_release.apk
```
첫 실행 때 권한 2개를 **허용**한다 — 차량 속도(`CAR_SPEED`, 대화상자에는 "위치 정보"로 보임)와 차량 위치(`FUSED_LOCATION`, "알 수 없는 작업"으로 보임). 대화상자 바깥을 누르면 거부로 처리되니 주의. 위치 권한이 없으면 지역 판정·쉼터 도착 감지가 동작하지 않는다. 거부했다면:
```bash
adb shell pm grant --user $(adb shell am get-current-user) com.nolleo.app android.car.permission.CAR_SPEED
adb shell pm grant --user $(adb shell am get-current-user) com.nolleo.app pleos.car.permission.FUSED_LOCATION
```

### 0.2 차량 상태 바꾸기 (Virtual Console)
```bash
adb forward tcp:8088 tcp:8088      # 브라우저로 http://127.0.0.1:8088/
```
- **Motion > Gear Selection**: P(주차) ↔ D(주행). 이 문서에서 "기어 P/D"는 모두 여기서 바꾼다.
- **Motion > Brake Pedal**: 신호대기(정차) 보조 신호. **Convenience > Seat Occupancy**: 동승자 감지 — 에뮬레이터에서는 앱 값이 바뀌지 않는다(§3.3).
- 터미널에서 바꾸고 싶으면(브라우저 세션 하트비트가 3초만 유효하므로 매번 같이 보낸다):
  ```bash
  curl -s -X POST "http://127.0.0.1:8088/browser/session?client=cli" >/dev/null
  curl -s -X PUT  "http://127.0.0.1:8088/vehicle/gear?gear=Drive"    # Park / Drive
  ```

### 0.3 위치 바꾸기
```bash
adb emu geo fix <경도> <위도>       # 경도가 먼저! 예) 서울 시청: adb emu geo fix 126.9780 37.5665
```
에뮬레이터 기본 위치는 해외라 국내 지역·졸음쉼터가 안 나온다. 위치를 쓰는 기능을 볼 때는 먼저 국내 좌표를 넣는다.

### 0.4 디버그 패널 (DEV)
앱 왼쪽 위 로고·제목 **"Nolleo"를 1초쯤 길게 누르면** 디버그 패널이 열린다(release 에도 있음, 상단에 DEV 표시). 닫기는 오른쪽 위 **닫기** 또는 Back. 이 문서에서 "패널"은 이것을 말한다. 에뮬레이터는 차가 움직이지 않고 마이크도 기본으로 꺼져 있어, 시연·시험에 필요한 가짜 입력(시뮬 여정·대본 응답·버튼)을 여기서 넣는다. 각 칸 설명은 [§11](#11-디버그-패널-안내).

권장 기본값 (시연·시험 공통, 앱을 새로 설치하면 다시 맞춘다):

| 패널 항목 | 값 | 이유 |
|---|---|---|
| 모드 > 데모 모드 | **켜짐** | 판당 6문제, 운전자 기준값이 없으면 1.5초로 시드, 졸음 쿨다운을 짧게(1단계 20초·2단계 60초) — 판단 규칙은 같음 |
| 여정 | **시뮬** + 시뮬 경로 **서울 → 부산** | 에뮬레이터 차는 움직이지 않아 실제 내비 남은 시간이 줄지 않는다. 시뮬은 실제 1분 = 여정 30분. 시뮬 경로는 여정 칸의 버튼으로 고르고, 홈 `목적지` 맨 위(현재 경로 자리)에 보인다(§3.2) |
| 음성 > 응답 입력 | **대본 normal** | 마이크 없이 답이 자동으로 들어옴(TTS 는 실제 Pleos 음성) |

> 버튼 줄은 체크(✓)가 붙은 버튼만큼 폭이 바뀌어 위치가 조금씩 달라진다. 화면을 보고 누른다.

### 0.5 로그 창 (선택)
```bash
adb logcat -v time -s Nolleo/ModeArbiter:I Nolleo/GameSession:I Nolleo/Coordinator:I Nolleo/NaviHelper:I Nolleo/TripRepo:I Nolleo/TimerTrip:I Nolleo/RestCare:I Nolleo/Location:I Nolleo/AaosCar:I Nolleo/IdiomQuiz:I Nolleo/RegionQuiz:I Nolleo/WordChain:I Nolleo/AudioFocus:I Nolleo/Window:I
```
release 빌드는 **인식한 말·위치와 관련된 로그를 `<redacted>` 로 가린다**(개인정보 보호). 쉼 장소 이름·좌표 같은 값은 패널 화면에서 보면 되고, 원문 로그가 필요하면 debug 빌드를 쓴다(`adb uninstall com.nolleo.app` 후 `./gradlew installDebug` — 서명이 달라 바로 덮어쓸 수 없음).

### 0.6 화면 읽는 법
- 왼쪽 위: 로고(차콜 바탕에 노란 언덕 길과 웃는 해) + 영문 제목 `Nolleo`. 그 밖에는 아무것도 없다(부제 없음).
- 제목 줄에는 입력 소스를 두지 않는다. 지금 쓰는 소스는 디버그 패널(§11) 각 칸 제목(`차량 — …`, `여정 — …`, `위치 — …`, `음성 — TTS … · STT …`)에서 본다. 시뮬 여정이면 음성 화면에 `시뮬레이션 여정` 칩이 보인다.
- 버튼·보기·선택 막대는 누르는 동안만 살짝 어두워지고 떼면 바로 돌아온다(물결 효과 없음).
- 글자 크기: 가장 작은 글자 21sp, 주행 화면 본문 33sp 이상(11/8 두 번 키움). 홈은 목적지 이름·카드 제목·설정 줄 이름·선택 막대·미리보기만 한 단계 크게, 설명·판 구성·안내 같은 서브 글씨는 기본 크기. 에뮬레이터는 160dpi 라 1sp = 1px 이다.
- 흰 카드는 회색 바탕보다 살짝 짙은 1dp 테두리로 가른다(밤에는 카드보다 살짝 밝은 테두리). 선택 막대의 고른 칸에도 가는 테두리(11/8).
- 음성 화면 첫 줄: 초록 점 + `음성 모드 · 도착까지 3시간 32분`(목적지 없이 정한 시간만큼 놀 때는 `남은 시간 29분`) / 멈췄을 때 회색 점 + `일시정지 · …`
- 칩: `1/5판 · 지역 퀴즈`, 지역 이름(`경기도`), `시뮬레이션 여정`
- 색 [실제]: 주간에는 연회색 바탕·흰 카드·검정 글, 시스템이 **야간 모드**면 차콜 바탕·흰 글로 바뀐다(앱을 다시 켜지 않아도 바로). 에뮬레이터에서는 `adb shell cmd uimode night yes` / `no` 로 바꿔 본다. 노랑은 주 버튼·고른 표시·안내 카드에만 쓴다. 꼭 봐야 하는 안내(말 걸기·쉬어 가기)는 **노란 안내 카드**(야간은 어두운 호박색 + 노란 테두리)로, 주 버튼은 화면마다 하나만 노란 알약이고 나머지는 테두리 버튼이다.
- 고른 목적지는 라디오 점 + 옅은 노랑 바탕, 선택 막대(운전·함께·게임·간격)는 고른 칸이 떠 보인다(주간 흰 칸, 야간 한 단계 밝은 회색 칸 — 색만으로 구분하지 않음). 운전자·가족 점수에는 이름 첫 글자 아바타(`아`빠, `엄`마)를 붙이고, 지금 차례인 사람은 채운 원으로 보인다.

### 0.7 용어
- **TBT (Turn-By-Turn)**: 내비가 "다음에 어디서 어떻게 가라"를 하나씩 알려 주는 길 안내 목록. 계기판·내비 화면의 "80m 앞 좌회전 · 기업지원허브 방면"이 TBT 다. Pleos NaviHelper SDK 가 이 목록을 앱에 넘겨 준다(`onTBTInfo`, 조회는 `getTBTInfo`). 항목마다 종류(`type`: 좌회전·IC 진입·톨게이트·**휴게소 진입 `TURN_ENTER_SERVICEAREA`**·**졸음쉼터 `TURN_RESTAREA`** …)·거리(`distance`, m)·설명(`description`, 예: "오산졸음쉼터")이 있다.
  ```
  좌회전         80 m   기업지원허브 방면
  우회전        380 m   판교IC 방면
  톨게이트     1000 m   서울톨게이트
  휴게소 진입 14000 m   기흥휴게소
  졸음쉼터     9300 m   오산졸음쉼터      ← 지금부터 거리는 앞 항목을 다 더한 약 30 km
  ```
  `distance` 는 "지금 위치부터"가 아니라 **바로 앞 항목부터의 거리**다(에뮬레이터에서 확인). 놀레오는 TBT 를 ① 회전·분기 직전 자동 일시정지(§6.1) ② 경로 위 휴게소·졸음쉼터 찾기(§8)에 쓴다. 시뮬 여정에서는 앱이 같은 형태의 안내를 흉내 낸다(패널 "TBT 분기점 300m").
- **DO (Distraction Optimization, 주행 규제)**: 주행 중 화면 조작을 제한하라는 플랫폼 신호(`CarUxRestrictions`). 기어 D 에서 `requiresDO=true` 가 오면 화면 게임·설정을 막고 음성으로만 진행한다.
- **시뮬 여정 / 대본 응답**: 에뮬레이터는 차가 움직이지 않고 마이크가 기본으로 꺼져 있어, 남은 시간이 줄어드는 가짜 여정(실제 1분 = 30분)과 미리 정한 답(대본)으로 흐름을 끝까지 보여 준다. 디버그 패널에서 켠다(§0.4). 시뮬 경로는 서울 → 부산 / 강릉 / 전주 / 근처 10분 네 가지(11/8 부터 홈이 아니라 패널에서 고른다).
- **시간 여정**: 홈의 `목적지 없이`(30분~2시간)로 출발하면 경로 없이 시간만 센다. 차를 세워 둔 동안에는 멈춘다(§3.2).

## 3. 홈: 여정 설정

### 3.1 목적지와 남은 시간 맞춤 판 짜기 [실제]+[시뮬]
- **무엇**: 목적지까지 남은 시간과 **판 간격**으로 판 수·판 길이를 정한다. 판 사이에는 말을 걸지 않는다.
- **홈 구성**: 카드 두 개뿐이다. 왼쪽 `목적지` 목록(현재 경로 · 최근 목적지 · 목적지 없이 — §3.2), 오른쪽 `오늘의 게임` 카드(미리보기 + **운전 / 함께 / 게임 / 간격** 선택 막대 네 줄 + 노란 **출발** 하나). 카드마다 맨 아래 가운데에 안내 한 줄 — 왼쪽 `남은 시간에 맞춰 판을 나눠요`, 오른쪽 `주행 중에는 음성으로, 정차 중에는 화면으로 놀아요`(넓은 창은 두 줄이 같은 높이). 좁은 창은 위아래로 놓고 스크롤(왼쪽 안내 줄은 시간 막대 바로 아래 가운데).
- **확인**
  1. 홈 `목적지`에서 줄 하나를 고른다(패널 여정 **시뮬**이면 맨 위의 시뮬 경로, 아니면 최근 목적지나 `목적지 없이`).
  2. `오늘의 게임` 카드의 **간격** 막대에서 **여유 있게 / 자주 / 쉬지 않고**를 바꿔 본다.
- **기대 결과** (시뮬 경로 서울 → 부산, 4시간 10분): 여유 있게 `5판 · 판 사이 약 39분` / 자주 `12판 · 약 10분` / 쉬지 않고 `20판 · 약 2분`. `목적지 없이 30분`은 `30분 → 1판 (판당 약 6분)`, `1시간`은 `1시간 → 1판 (판당 약 10분)`(여유 있게, 11/8 확인). 데모 모드면 `데모 모드: 판당 6문제`. 고른 간격은 다음 실행에도 남는다.
- 주행 중 남은 시간이 ±20% 넘게 바뀌면 남은 판만 다시 짠다(로그 `SessionPlanner: remain … → … (±20%↑)`). 쉬는 시간·"오늘 준비한 판을 모두 했어요" 중에도 새 계획의 판을 기다리고(늘어난 시간에 더해진 판도 시작), 판 진행 중에 다시 짜면 그 판이 끝난 때 한 번 더 짜서 다음 판 앞에 최소 휴지(2분)를 둔다(로그 `판 진행 중 다시 계획함 → …`). 시뮬 여정은 남은 시간이 예상대로 줄어 보통 다시 짜지 않는다.
- 남은 시간이 5분 이하면 미리보기가 `4분 → 곧 도착이라 게임을 시작하지 않아요` 이고, **출발**을 눌러도 같은 안내만 뜬다(시작하자마자 "곧 도착"으로 끝나지 않게). 현재 경로·최근 목적지가 거의 다 왔을 때만 생긴다 — 에뮬레이터 차 위치가 소프트웨어드림센터 옆이라 그 최근 목적지는 `약 1분 미만`이다.
- 시뮬 경로 3종(부산·강릉·전주)의 경로 위 휴게소·졸음쉼터 목록은 에뮬레이터 순정 내비가 같은 목적지로 준 것이다. 서울 → 부산은 경유 지점도 내비가 안내하는 길(영동선 → 중부내륙선 → 대구 → 청도)로 맞췄다.

### 3.2 목적지 목록: 현재 경로 · 최근 목적지 · 목적지 없이 [실제]
- **무엇**: 11/8 부터 홈에 고정 프리셋을 두지 않는다. 목록은 많아야 4줄이다(주행 중 긴 목록 금지).

| 줄 | 언제 보이나 | 출발하면 |
|---|---|---|
| `현재 경로: ○○` · `내비 길 안내 그대로` · 남은 시간 | 내비에 길 안내가 있을 때 | 경로 요청 없이 내비의 남은 시간을 쓴다 |
| 최근 목적지 이름 · `최근 목적지 · 주소` · `약 4시간 6분` | 길 안내가 **없을 때**, 내비 최근 목적지 앞 3곳 | 그곳으로 길 안내를 요청한다(`requestRoute`) → 순정 내비가 앞으로 나와 안내 시작 → 놀레오가 다시 앞으로(아래) → 내비의 남은 시간 |
| `목적지 없이` · `정한 시간만큼 놀아요` + 시간 막대 `30분 · 1시간 · 1시간 반 · 2시간` | 늘 | 정한 시간만큼 논다(시간 여정) |
| (패널 여정 **시뮬**) `서울 → 부산` · `시뮬 여정 · 부산역` · `약 4시간 10분` | 현재 경로 자리. 이때는 실제 내비 줄(현재 경로·최근 목적지)을 숨긴다 | 시뮬 경로 (시연용) |

- **최근 목적지**: NaviHelper `getRecentDestinationInfo` → `onRecentDestinationInfo`. 예상 시간은 곳마다 `requestTrip` → `onTripInfo` 로 받는다 — **길 안내는 시작하지 않는다**(11/8 에뮬레이터 확인). 이 응답은 다른 앱의 요청에도 모든 연결 앱에 오고 요청 번호가 없어서, 한 곳씩 묻고 응답의 목적지 좌표로 맞춘다(5초 안에 답이 없으면 다음 곳). 이름이 비었거나 좌표가 0인 곳(등록 안 된 집·회사 등)은 뺀다.
  - 고르기만 해서는 내비를 바꾸지 않는다. **출발**을 누를 때 길 안내를 건다.
  - **출발 뒤 화면**: 놀레오가 앱 영역 전체를 쓰고 있으면 순정 내비가 전체를 덮는다(내비가 스스로 앞에 나옴). 놀레오는 길 안내가 시작되면(`onRouteStarted`, 에뮬레이터 약 7초) **스스로 다시 앞으로 온다**(로그 `내비 길 안내 시작 → 놀레오를 다시 앞으로`). 내비 길 안내는 계속되고 Driving view 에 회전 안내가 보인다. 이미 3분할(Driving view | 내비 | 놀레오)이면 내비가 가운데 창에서 안내를 시작하고 놀레오는 그대로 보인다. 앱이 3분할을 직접 만들 수는 없다(§10).
  - 길 안내 중에는 숨긴다 — 고르면 운전자의 길 안내를 바꾸게 된다. 그 사이 골라 둔 최근 목적지는 현재 경로로 본다.
  - 예상 시간을 아직 못 받았으면 줄 오른쪽 `시간 확인 중`, 미리보기 `예상 시간을 확인하고 있어요. 받으면 남은 시간에 맞춰 판을 짜 드려요.`, 출발하면 `예상 시간을 확인하고 있어요. 잠시 후 다시 눌러 주세요.`
  - 패널 여정이 **자동**인데 내비가 길 안내를 시작하지 못하면(미연결·`onError`·60초 동안 이벤트 없음) 출발 전에 받은 예상 시간으로 시간만 센다(패널 `여정 — 시간 여정 (폴백: …)`). **실제**면 대신 세지 않는다.
  - 새로 설치한 에뮬레이터는 최근 목적지가 없다 — 순정 내비에서 한 번 길 안내를 하면 생긴다.
- **목적지 없이**: 시간 칸을 누르면 그 시간으로 `목적지 없이`를 고른다. 마지막으로 출발한 시간은 다음 실행에도 남는다. 세션은 시간 여정으로 돈다.
  - 차를 세워 둔 동안(주차)과 쉬어 가기를 묻는 동안에는 시간이 흐르지 않는다(실제 내비의 남은 시간도 정차 중엔 그대로). 패널 여정이 **시뮬**이면 시뮬 배율로 흐른다.
  - 상단 `남은 시간 29분`(화면 게임 칩도 `남은 시간 30분`), 판 마무리 "정한 시간이 거의 다 됐어요. 이번 판은 여기까지 할게요!", 끝 인사 "정한 시간이 다 됐어요! 오늘 놀레오는 여기까지예요. …", 요약 제목 `시간이 다 됐어요` · `목적지 없이 30분`.
  - 경로가 없으므로 지역은 위치(FusedLocation)로 판정하고, 분기점 자동 일시정지는 없고, 쉬어 갈 곳은 졸음쉼터 표에서 고른다(§8.6).
  - 다른 여정처럼 남은 5분에 결과를 정리한다(30분이면 약 25분 논다).
- **고른 줄이 바뀌는 때**: 길 안내가 새로 생기면 `현재 경로`를 고르고, 끝나면 `목적지 없이`로 돌아간다(로그 `current route available → 홈에서 현재 경로` / `no current route → 최근 목적지·목적지 없이`). 게임 중에는 홈을 건드리지 않는다. 패널 여정을 **시뮬**로 바꾸면 시뮬 경로를 고른다.
- **확인** (11/8 에뮬레이터, 패널 여정 **자동**, release):
  1. 길 안내가 없는 홈 → `부산역 · 최근 목적지 · 부산광역시 동구 중앙대로 206 · 약 4시간 6분`, `소프트웨어드림센터 · … · 약 1분 미만`, `목적지 없이 · 1시간`(선택). 로그 `onRecentDestinationInfo 2곳 → 쓸 수 있는 곳 2곳`, `onTripInfo → 예상 4시간 6분`.
  2. **부산역** → 미리보기 `4시간 6분 → 5판 (판당 약 10분)` → **출발** → 순정 내비가 앞으로 나와 안내 시작. 로그 `requestRoute (poiId=<none>)`, `session start (Place) → …`, `onRouteStarted raw duration=14820 distance=378000`. 놀레오에서 `도착까지 4시간 7분`. (11/8 저녁부터는 길 안내가 시작되면 놀레오가 스스로 돌아온다 — 더현대서울로 확인: 0.4초 뒤 내비가 덮고 6.7초 뒤 `onRouteStarted` → 놀레오 정차 화면 게임 `도착까지 39분`, 3분할에서는 내비가 가운데 창에서만 안내.)
  3. **게임 끝내기** → 홈 `현재 경로: 부산역 · 내비 길 안내 그대로 · 4시간 7분`(선택)과 `목적지 없이`만 보이고 최근 목적지는 숨겨진다. 내비 길 안내는 그대로.
  4. **30분** 칸 → `목적지 없이 · 30분` 선택, 미리보기 `30분 → 1판 (판당 약 6분)` → **출발** → 로그 `timer trip 30분 (x1.0)`, `session start (Timer) → …`, 칩 `남은 시간 30분` → 기어 **D** → `일시정지 · 남은 시간 29분`.
  5. 패널 **남은 5분으로** → 주행 중 요약 `시간이 다 됐어요` → 기어 **P** → 전체 요약 `시간이 다 됐어요 · 목적지 없이 30분`.
  6. 순정 내비에서 **안내 종료** → 놀레오 홈이 최근 목적지 + `목적지 없이`(선택)로 돌아온다(로그 `onRouteCancelled`).
- 놀레오를 켜기 **전에** 길 안내를 시작했어도, 연결할 때 조회한 경로 상태(`onRouteStateInfo isRouting=true`)로 내비 상태를 채워 30초마다 남은 시간을 다시 조회한다. 내비가 리스너 등록 때 상태를 따로 보내 주는지는 확인 못 함(코드 규칙).
- 실차 내비가 최근 목적지·`requestTrip` 에 에뮬레이터처럼 답하는지는 확인 못 함(답하지 않으면 최근 목적지가 `시간 확인 중`으로 남아 그 줄로는 출발할 수 없다).

### 3.3 운전자·동승자, 좌석 센서 [실제]
- **확인**: 홈의 `함께` 막대 아래를 본다. Virtual Console **Convenience > Seat Occupancy** 로 바꿔 보아도 된다.
- **에뮬레이터에서는**: 에뮬레이터의 Pleos Vehicle SDK 는 동승석 4곳(조수석·뒷좌석 왼쪽·가운데·오른쪽)을 처음부터 모두 착좌로 보내고, Virtual Console 의 Seat Occupancy 를 바꿔도 값이 바뀌지 않는다(앱을 다시 켜도 같음). 그래서 늘 "3명"(앱이 고를 수 있는 최대)을 제안한다. 디버그 패널 차량 칸에서 `Seat 사용 가능 ROW_2_RIGHT=착좌, ROW_1_RIGHT=착좌, ROW_2_CENTER=착좌, ROW_2_LEFT=착좌` 로 확인. 실차에서 실제 착좌가 반영되는지는 확인 못 함.
- **기대 결과**: `함께` 막대 아래에 `좌석 센서가 동승자 N명을 감지했어요` + **N명으로**(이미 같은 수면 안 보임). 동승자 이름은 좌석 순서(조수석 · 뒷좌석 왼쪽 · 뒷좌석 오른쪽).

### 3.4 게임 선택
`지역 퀴즈` / `끝말잇기` / `번갈아`(판마다 번갈아) / `랜덤`. 미리보기에 `1판 지역 퀴즈 · 2판 끝말잇기 …`(랜덤은 보이지 않음 — 아래).
- **랜덤**(11/8): 판마다 지역 퀴즈·끝말잇기 중 무작위로 고른다. 같은 게임이 세 판 넘게 이어지지 않는다(앞 두 판이 같으면 셋째 판은 다른 게임). **랜덤**을 누를 때마다(이미 골라져 있어도) 다시 섞고, 앱을 켤 때도 새로 섞는다. 순서는 출발 전에 정해지지만 **미리보기에는 보이지 않는다** — `판마다 무엇이 나올지는 시작해야 알아요`(11/8 사용자 요청: 모르고 시작하는 재미). 판이 시작될 때 "1번째 판! 끝말잇기를 시작할게요…"와 음성 화면 칩 `1/6판 · 끝말잇기`로 알게 된다(다음 판은 미리 알리지 않음). 남은 시간이 바뀌어 판을 다시 짜도 같은 순서를 이어 쓴다(보너스 판 포함). 이어서 하기 저장본에도 순서의 씨앗(`gameSeed`)을 넣어 같은 순서로 이어 간다(예전 저장본은 0).
- **확인**: 홈 `게임` 막대의 **랜덤** → 미리보기 첫 줄 `2시간 → 6판 (판당 약 9분)` 아래가 판 구성 대신 `판마다 무엇이 나올지는 시작해야 알아요`(11/8 확인) → 출발하면 판마다 그 판의 게임을 알린다. 순서가 판마다 무작위이고 세 판 연속 같은 게임이 없는지는 단위 테스트(`SessionPlannerTest`)로 본다 — 화면에는 순서가 나오지 않는다.

### 3.5 주행 중 설정 제한 [실제]
- **확인**: 게임을 시작하지 않은 상태에서 기어 **D**.
- **기대 결과**: 홈이 `주행 중에는 여정 설정을 할 수 없어요 / 정차한 뒤에 목적지와 게임을 골라 주세요.` + **이전 설정으로 출발** 버튼만 남는다(CarUxRestrictions `NO_SETUP` 비트, 로그 `UX restrictions: requiresDO=true active=80`). 이어서 할 여정이 있으면 위 배너의 **이어서 하기**가 노란 버튼이고 **이전 설정으로 출발**은 테두리 버튼이다(채운 버튼은 화면에 하나). 패널의 텍스트 입력칸도 `주행 중 입력 불가`.

## 4. 주행·정차에 따라 바뀌는 모드 [실제]

| 상태 | 화면 | 판단 근거 |
|---|---|---|
| 기어 D (주행) | **음성 모드** — 문제를 말로 내고 말로 답한다. 버튼은 큰 것 1개, 글은 3줄 이하 | AAOS `GEAR_SELECTION`·`PERF_VEHICLE_SPEED`, 주행 규제(DO) |
| 정차(신호대기) | 음성 모드 유지 | 저속 3초 또는 속도 0 + 브레이크 |
| 기어 P (주차) | **화면 모드** — 화면 게임(사자성어 · 지역 퀴즈 · 끝말잇기) | 주차 && 규제 없음 |

- **확인**: 게임 중 기어 P ↔ D 를 바꾼다.
- **기대 결과**
  - P → D: 0.1초 안에 음성 모드(로그 `ModeArbiter: PARKED+DO → VOICE (from=SCREEN, reason=distraction-optimization)`), 1.5초 뒤 `DRIVING`.
  - D → P: 진행 중인 차례만 마치고 "차가 멈췄네요. 이번 판은 여기까지 할게요! 화면 게임이 열렸어요." → 화면 모드(`PARKED → SCREEN`).
  - 화면 게임 중 D: 화면 게임이 즉시 닫히고(읽던 화면 게임 음성, 정차 끝말잇기의 말하기·듣기도 즉시 멈춤) 음성으로.

## 5. 음성 게임 (주행 중)

### 5.1 지역 퀴즈 [실제]+[시뮬]
- **무엇**: 지금 지나는 시/도(17곳)의 특산물·지명·문화 문제. 지역이 바뀌면 "이제 ○○예요!".
- **지역을 정하는 순서**: 패널 위치 **자동**이면 시뮬 여정 중에는 시뮬 경로, 아니면 FusedLocation → 내비 주소 → 시뮬. **실제**는 FusedLocation 우선, **시/도 버튼**은 강제 지정.
- **확인 (실제 위치)**
  1. 패널 위치 = **실제**(또는 여정 = 자동으로 게임).
  2. `adb emu geo fix 126.9780 37.5665`(서울 시청).
- **기대 결과**: 패널 `위치 — FusedLocation: 서울특별시`, 로그 `Location: region=seoul via FusedLocation`, 다음 지역 퀴즈는 서울 문제, 음성 화면 배지 `서울특별시`.
- 시뮬 경로 서울 → 부산은 시간이 흐르며 서울 → 경기 → 충북 → 경북 → 대구 → 경북 → 부산으로 바뀐다. 목적지 없이(시간 여정)는 위치(FusedLocation)로 판정한다.

### 5.2 끝말잇기 [실제]
- 순서: 놀레오 → 운전자 → 동승자. 두음법칙은 ㄹ·ㄴ 초성 **양방향**으로 인정한다(력↔역, 래↔내, 리↔니↔이 — 안내 문구는 표준 방향 "'력'이나 '역'으로").
- 사람 답은 **검증용 사전**(국립국어원 사전 기반 194,197 낱말)으로 판정하고, 없는 말은 "다시 한번 말해 줄래요?" 뒤 너그럽게 인정한다(로그에 남음). 검증용은 출발할 때 백그라운드에서 읽는다(로그 `Content: valid words loaded in …ms`).
- 놀레오는 **출제용 사전**(한국어기초사전 기반 7,844 낱말)에서만, 졸음 케어 난이도 상한에 맞는 등급(상한 1 초급만 · 2 초급·중급·팀목록 · 3 전부)으로 고른다. 이을 말이 거의 없는 음절로 끝나는 낱말은 피하고, 그런 말밖에 없으면 "이 말은 잇기 어렵네요, 다른 말로 다시 시작할까요?" 뒤 새 낱말로 이어 간다. 이을 말이 아예 없으면 "제가 졌어요!"로 그 판을 끝낸다(화면 글은 `놀레오: 제가 졌어요`).
- 첫 낱말과 다시 시작하는 낱말도 같은 규칙이다 — 난이도 상한 안의 말을 먼저(그다음 기본 시작말 목록 "기차·나무·사과…", 없으면 등급을 넓힘), 그리고 아직 안 쓴 이을 말이 남은 말만 고른다.
- 사람 답에서 존댓말 어미("요"·"이에요"·"예요"·"입니다")는 떼고 판정하지만, "동요"·"필요"·"대중가요"처럼 **"요"까지가 낱말이면 떼지 않는다**(사전에 원형만 있으면 원형).
- 요약의 `끝말잇기 최장 N개 낱말`은 한 판에 이은 낱말 수다 — 다른 말로 다시 시작한 전후를 합쳐 센다(11/8 결정).
- **남은 초**(11/8): 사람 차례에 듣기 시작하면 문제 카드 가운데에 답을 시작해야 하는 남은 초를 크게(`8` `초 안에 말해요`) 보여 준다. 숫자만 1초에 한 번 바뀌고(움직이는 효과 없음 — 주행 중 애니메이션 금지), 3초 이하는 빨강. 말을 시작하면(소리 감지·부분 인식) 바로 사라지고, 0초가 되면 무응답으로 넘어간다(§5.3). 지역 퀴즈에는 띄우지 않는다.
- **낱말 줄**(11/8): 정차 중 끝말잇기(§7.3)와 같은 모양으로 문제 카드 맨 위에 이어진 낱말을 보인다 — 마지막 4개(`… 산업 → 업적 → 적자 → 자연`), 지금 이을 말은 테두리 칸, 창이 좁으면 앞 낱말부터 빼서 한 줄에 들어가는 만큼. 그 아래 차례와 `'연'으로 시작하는 말`(화면 글은 무엇으로 시작할지만 — 전에는 `자동차 → '차'로 시작하는 말`). 다른 말로 다시 시작하면 화면 글 첫 줄이 `다른 말로 다시 시작`.
  - 줄은 다음 차례 글과 같은 때 바뀐다 — 답을 이은 직후 칭찬하는 동안은 앞 줄 그대로이고 아래 `운전자: 산업 → '산업' 성공` 줄로 보인다(줄과 "무엇으로 시작" 글이 어긋나지 않게).
  - 글자 수 제한 규제(LIMIT_STRING_LENGTH)면 줄 없이 `'차' 시작` 한 줄만.
- **확인**: 게임 **끝말잇기** 또는 **번갈아**의 2판. 패널 응답 입력 **대본 normal** 이면 낱말 줄이 차례마다 늘어난다(11/8 넓은 창·3분할 확인). 응답 입력이 **마이크**이고 말하지 않으면 남은 초가 8 → 0 으로 줄어드는 것이 보인다(대본 normal 은 1~2.5초 만에 답해 금방 사라짐).

### 5.3 답하는 방법
| 패널 응답 입력 | 동작 |
|---|---|
| **마이크** | Pleos STT 로 실제 인식. 에뮬레이터 *Extended Controls(⋯) > Microphone > Virtual microphone uses host audio input* 을 켜야 함 |
| **대본 normal** | 1~2.5초 뒤 대부분 정답 |
| **대본 sleepy** | 운전자 차례만 2초 → 3.5 → 4.5 → 6 → 6.5초 → 무응답… 으로 느려짐(동승자는 평소 속도). 졸음 케어 시험용 |
| **직접 입력** | 패널의 **정답 / 오답 / 무응답** 버튼이나 텍스트(주차 중만)로 그때그때 답 |

- 8초 안에 말이 없으면 무응답 처리. 화면 아래 `아빠: (인식한 말) → 정답` 한 줄(규제 비트가 있으면 숨김).
- 인식 오류(네트워크·오디오 등 — 무응답과 다름)로 끝난 답은 졸음 지표에 넣지 않는다(로그 `Drowsiness: 샘플 제외(인식 오류 …)`). 치명 오류면 그 엔진을 "사용 불가"로 내려 같은 문제를 다른 엔진으로 다시 내고, 다음 출발·앱 복귀 때 한 번 다시 초기화한다.
- "다시 한번 말해 줄래요?" 뒤 두 번째로 듣는 중에 일시정지되면, 재개 1초 뒤 같은 문제부터 다시 낸다(무응답으로 넘기지 않음).
- 쉬어 가기 질문의 "네/아니요"도 같은 입력을 쓴다(대본 엔진은 1.5초 뒤 "네").

### 5.4 판·쉬는 시간
- 판이 끝나면 `쉬는 시간이에요 / 다음 판은 약 N분 뒤에 시작해요 / 판 사이에는 말을 걸지 않아요 · 바로 하려면 '지금 시작'`.
- 버튼: **지금 시작**(바로 다음 판), 모든 판을 마치면 **한 판 더**.

## 6. 운전에 집중할 순간 자동 일시정지

### 6.1 길 안내(TBT) [실제 이벤트]+[시뮬 버튼]
- **무엇**: 내비의 다음 안내가 분기·진출입·회전이고 500 m 안이면 즉시 멈추고(TTS·STT 중단), 지나가면 같은 문제를 다시 낸다.
- **확인**: 게임 중 패널 → **TBT 분기점 300m** → Back.
- **기대 결과**: `길 안내 후 이어서 할게요 / 분기점·회전 안내 구간이에요` → 안내 구간을 지나면(시뮬 안내 8초 + 지난 뒤 3초, 약 11초) 같은 문제부터 다시. 로그 `TBT … → 자동 일시정지`.
- 실제 내비 여정에서도 에뮬레이터 내비가 `TURN_LEFT 80m` 를 보내 멈춘다. 차가 움직이지 않아 같은 안내가 20초 넘게 그대로면 정체/정차로 보고 풀린다(로그 `TBT 안내가 20초 넘게 그대로 → 정체/정차로 보고 재개`). 시뮬 여정은 시뮬 경로마다 정해진 지점(부산 45·160분, 강릉 30·100분, 전주 40·115분, 근처 10분 3분)에서 스스로 TBT 를 낸다. 목적지 없이(시간 여정)는 경로가 없어 길 안내 일시정지가 없다.

### 6.2 통화·음성비서(Gleo)·다른 미디어 앱 [불가]
- **통화·Gleo**(일시 손실 `AUDIOFOCUS_LOSS_TRANSIENT`): 즉시 멈추고(`통화가 끝나면 이어서 할게요`) 돌려받으면 1초 뒤 같은 문제.
- **다른 미디어 앱이 소리를 가져감**(영구 손실 `AUDIOFOCUS_LOSS`): 세션을 끝내지 않고 즉시 멈춰 `소리를 낼 수 없어요 / 잠시 후 계속을 눌러 주세요` + 상태 저장. 영구 손실 뒤에는 포커스가 돌아오지 않으므로 **계속**을 눌러야 같은 문제부터 이어진다(자동 재개 없음, 11/8 결정). 로그 `AUDIOFOCUS_LOSS → 일시정지(상태 저장), 계속을 누르면 이어서`.
- 통화로 멈춘 동안 포커스 요청이 사라지면(예: 정차 중 화면 게임이 포커스를 잡았다 반납) 통화 일시정지도 **계속**으로 풀리게 바뀐다(로그 `focus request dropped during AUDIO_FOCUS pause`). 세션이 끝나면 통화 중이어도 포커스 요청을 거둔다.
- 우리 Pleos TTS 가 말하는 중에 생긴 손실은 Speech Service 자체 포커스로 보고 무시한다.
- 에뮬레이터에서 통화·Gleo·영구 손실을 만들지 못해 코드·단위 테스트(`SessionFocusPolicyTest`)만 있다.

### 6.3 직접 멈추기
음성 화면 오른쪽 아래 **일시정지** → `잠시 멈췄어요 / 계속을 누르면 같은 문제부터 다시 들려 드려요` → **계속**. 멈춘 동안에는 **게임 끝내기**도 보인다.

## 7. 화면 게임 (정차 중): 사자성어 · 지역 퀴즈 · 끝말잇기 [실제]
- **목록**: 기어 **P** 로 `정차 중 · 화면 게임`. 넓은 창은 위에 열 수 있는 카드 3개(**사자성어** `溫 故 知 新`, **지역 퀴즈** `지금 지나는 곳` + 지금 시/도 이름(모르면 `위치를 모르면 전국에서` + `우리나라`), **끝말잇기** `기차 → 차표 → 표범`)와 각 카드의 **시작하기**(테두리 버튼, 카드 아무 곳을 눌러도 됨), 아래에 낮은 준비 중 카드 2개(**틀린 그림 찾기** `?`, **노래방** `♪`, `준비 중이에요`, 눌리지 않음). 좁은 창은 위아래로 쌓고 스크롤. 위쪽 머리 줄 `정차 중 · 화면 게임` · `도착까지 …` · **게임 끝내기**, 아래 줄 `정차 중에만 열려요 · 출발하면 음성 게임으로 바뀌어요 · 다음 음성 판: 주행 약 N분 뒤`.
- 사자성어·지역 퀴즈는 보기를 누르는 게임, 끝말잇기는 **말로 잇는** 게임이다(11/8 저녁부터 — 전에는 끝말잇기도 넷 중 고르기). 아래 공통 화면·버튼·소리 규칙은 사자성어·지역 퀴즈 이야기이고, 끝말잇기는 §7.3.
- **공통 화면**(사자성어·지역 퀴즈): 게임을 열면 정차 화면 머리 줄은 숨기고 머리 줄 하나만 — **← 목록** · `제목` + 점수 칩 `N점` + 상태 줄(`읽어 주는 중이에요` → `곧 다음 문제로 넘어가요` → `N문제 중 M개 맞혔어요`) · **다시 듣기**. 그 아래 **가운데 맞춘 위아래 배치**: 작은 글(문제 갈래) → 문제 → 보기(2열) → 고르면 풀이 카드(결과 → 게임별 풀이 → 가운데 노란 **다음 문제**). 넓은 창·3분할 좁은 창 모두 같은 배치. 고르면 정답 초록·고른 오답 빨강·나머지 흐리게(고른 뒤에는 보기가 눌리지 않음), 화면에 `정답이에요 · +10점` / `아쉬워요 · 정답은 ○○`. 맞히면 10점, 점수는 게임마다 그 세션 동안 유지(새 게임에서 0점부터). **주행 중 음성 판과는 따로 논다** — 점수·진행이 음성 판에 이어지지 않는다.
- **버튼**(사자성어·지역 퀴즈): **다시 듣기**(고르기 전 = 문제, 고른 뒤 = 결과·풀이를 다시 읽고 다음 문제로), **다음 문제**(읽는 중이어도 바로), **← 목록**/Back(읽기를 멈추고 목록으로 — 점수·풀던 문제는 남고, 다시 열면 풀던 문제를 다시 읽어 준다).
- **소리 규칙**(사자성어·지역 퀴즈 — 끝말잇기도 멈추는 경우는 같다): 읽는 동안만 오디오 포커스(`GAIN_TRANSIENT_MAY_DUCK`)를 잡고 다 읽으면 반납. 출발(기어 D·주행 규제)·← 목록·다른 앱이 창을 덮음·게임 끝내기·음성 게임 발화 때 **즉시 멈춤**, 통화·Gleo 로 포커스를 잃으면 멈추고 `소리가 멈췄어요 · 다시 듣기나 다음 문제를 눌러 주세요` — 저절로 이어 읽지 않는다. 다 읽은 뒤 적어도 2.5초, 고른 때부터 적어도 게임별 시간(사자성어 10초 · 지역 퀴즈 5초) 뒤 저절로 다음 문제. 읽는 중에 보기를 누르거나 **다음 문제**·**다시 듣기**를 눌러도 새 발화를 끝까지 읽는다 — 끊은 발화의 늦은 종료 신호는 무시한다(로그 `PleosSpeech: TTS … from an utterance we stopped → ignored`, 11/8 확인). 정차 중 세션이 끝나면 열어 둔 게임은 닫히고, 다음 세션의 정차 화면은 게임 목록부터.

### 7.1 사자성어
- **무엇**: 주차 중에 사자성어를 익히는 4지선다. 힌트는 쓰지 않는다.
  1. 뜻(문제)을 화면에 보여 주고 TTS 로 읽는다 ("다음 뜻을 가진 사자성어는? …").
  2. 보기 4개 중 하나를 고르면 정답 사자성어의 **한자 4글자와 글자마다 훈·음**(예: 家 `집 가`)을 보여 주고 "정답! 가가호호." / "아쉬워요. 정답은 가가호호."를 읽는다.
  3. **유래가 있으면** 이어서 유래를 읽는다(화면에는 `유래` 아래 원문).
  4. 다음 문제로 넘어가 1부터 다시. 유래가 없으면 정답만 읽어 금방 끝나므로 고른 때부터 적어도 10초는 한자 풀이를 보여 준다.
- **콘텐츠**: `assets/content/quiz_idioms.json` 1,014개(그중 유래 있는 것 210개). 출처는 국립국어원 《표준국어대사전》(뜻풀이·유래)과 한자 훈·음 자료, 파일의 배포 조건은 CC BY-SA 4.0 — 자세한 것은 [`CONTENT_SOURCES.md`](CONTENT_SOURCES.md). 한 바퀴를 다 돌 때까지 같은 문제를 다시 내지 않는다. 오답 보기는 뜻이 같은 사자성어(예: 군맹무상·군맹평상)를 빼고, 난이도가 같은 것에서 먼저 고른다.
- **읽기용 문장**: 화면에는 원문 그대로, 소리로는 한자 괄호 `인척(姻戚)`·책 표시 `≪ ≫ < >`·따옴표를 빼고 `·` 는 쉼표로 읽는다.
- **확인**: 게임 중 기어 **P** → 카드 **사자성어**의 **시작하기** → 보기 하나 터치 → 기다리기.
- **기대 결과**
  - 풀이 카드: 결과 → 한자 칸 4개(한자 + `훈 음`) → (있으면) `유래` 와 원문 → **다음 문제**.
  - 로그 `IdiomQuiz: open`, `IdiomQuiz: answer <id>: 정답 (score=10, 1/1)`, 읽을 때마다 `AudioFocus: request GAIN_TRANSIENT_MAY_DUCK … GRANTED` → 다 읽으면 `abandon focus`.

### 7.2 지역 퀴즈 (정차 중)
- **무엇**: 지금 지나는 시/도(음성 지역 퀴즈와 같은 위치 판정 — §5.1, 패널 위치 칸에서 강제 지정 가능)의 지역 퀴즈 문제를 화면에서 고른다. 위치를 모르면 전국에서. 한 바퀴를 다 돌 때까지 같은 문제를 다시 내지 않는다.
  - 문제 글에 두 보기가 들어 있으면("…불국사일까요, 경복궁일까요?") 그 두 개만 보기로, 아니면 정답 + 같은 갈래(음식·지명·문화·특산물) 다른 문제의 정답 3개 = 4지선다.
  - 고르면 "딩동댕! 경복궁이에요." / "아쉬워요. 정답은 경복궁이에요." + 힌트 문장을 읽고, 풀이 카드에 힌트(예: `광화문을 지나면 나오는 궁궐이에요`)를 보여 준다.
- **확인**: 기어 **P** → **지역 퀴즈**의 **시작하기** → 작은 글 `지금 지나는 곳 · 서울특별시` + 문제 + 보기 → 하나 고르기. 패널 위치 칸에서 다른 시/도를 고르고 다시 열면 그 지역 문제가 나온다.
- 로그 `RegionQuiz: open`, `RegionQuiz: answer seoul-03: 정답 (score=10, 1/1)`.

### 7.3 끝말잇기 (정차 중)
- **무엇**: 주행 중 음성 끝말잇기(§5.2)와 같은 규칙으로 놀레오 → 운전자 → 동승자 차례로 **말로** 잇는다(11/8 사용자 요청 — 전에는 이어질 말을 넷 중에서 고르기). 두음법칙 양방향, 사람 답은 검증용 사전으로 판정(없는 말은 "다시 한번 말해 줄래요?" 뒤 너그럽게 인정), 놀레오는 출제용 사전에서 고른다. 정차 중에는 졸음 케어가 없어 난이도 상한을 두지 않는다(전부). 이으면 10점.
  - 사람 차례에는 8초 안에 말을 시작해야 한다 — 가운데에 남은 초(§5.2 와 같은 표시). 말이 없으면 "시간이 다 됐어요! 다음 사람이 이어 볼까요?" 뒤 다음 사람에게 같은 음절이 넘어간다.
  - 사람 수만큼(적어도 2번) 잇달아 대답이 없으면 "대답이 없어서 끝말잇기는 여기까지 할게요. 모두 N개 낱말을 이었어요."로 끝낸다 — 아무도 하지 않는데 마이크를 계속 열어 두지 않게. 놀레오가 이을 말이 없으면 "제가 졌어요!" 뒤 끝.
- **화면**: 머리 줄 **← 목록** · `끝말잇기` + 점수 칩 + 상태 줄(`놀레오가 말하는 중이에요` / `듣고 있어요 · 낱말 하나를 말해요`) · **새로 시작**. 남은 높이 가운데에 이어진 낱말(주행 중 음성 화면과 같은 낱말 줄 — 마지막 4개, 앞이 더 있으면 `…`, 지금 이을 말은 테두리 칸, 좁은 창이면 들어가는 만큼) → 아바타 + `운전자 차례` → `'차'로 시작하는 말`(크게) → (듣는 중) 남은 초 → 마이크 상태 → `운전자: 차례 → '차례' 성공`. 끝나면 카드 `대답이 없어서 멈췄어요`(또는 `놀레오가 졌어요`) · `모두 N개 낱말을 이었어요 · M점` · 노란 **다시 하기**.
- **멈춤·이어 하기**: **← 목록**/Back·출발(기어 D)·다른 앱이 덮음·게임 끝내기·음성 게임 발화·포커스 손실이면 말하기·듣기를 즉시 멈춘다. 다시 열면 이은 낱말은 그대로 두고 멈춘 사람에게 같은 음절을 다시 묻는다(시작 안내는 다시 하지 않음). 통화·Gleo 로 포커스를 잃어 멈추면 카드 `소리가 멈췄어요` + **이어서 하기** — 저절로 다시 하지 않는다. 기록은 세션 동안 남고 새 세션에서 처음부터. 음성 판과는 따로 논다(점수·낱말이 이어지지 않음).
- **소리**: 판이 도는 동안(말하기·듣기) 오디오 포커스 `GAIN_TRANSIENT_MAY_DUCK` 를 들고 있다가 끝나거나 멈추면 반납한다.
- **확인**(11/8 에뮬레이터, release, 동승자 1명):
  1. 패널 응답 입력 **대본 normal** → 기어 **P** → **끝말잇기**의 **시작하기** → "끝말잇기를 시작할게요! 제가 먼저 할게요." → `기차 → 차례 → 예절 → 절약 → 약점`처럼 이어지고(`'례'나 '예'로 시작하는 말` — 두음법칙) 점수 칩이 10점씩 오른다.
  2. **← 목록** → 다시 **시작하기** → 같은 차례부터 이어진다(로그 `stop (close)` → `open (words=11)`).
  3. 기어 **D** → 즉시 멈추고 음성 모드(로그 `stop (mode=VOICE)`, `abandon focus`).
  4. 응답 입력 **마이크**에서 말하지 않으면 남은 초가 8 → 0 으로 줄고(3초부터 빨강), 운전자·조수석이 잇달아 무응답 → `대답이 없어서 멈췄어요` · `모두 1개 낱말을 이었어요 · 0점` + **다시 하기**(로그 `end: NO_ANSWER (1개)`).
- 로그 `WordChain: open (words=0)`, `운전자: CORRECT (2개)`, `조수석: WRONG (5개)`, `end: NO_ANSWER (1개)`. 들은 말은 `heard(운전자)=…`(release 는 `<redacted>`).

## 8. 졸음 케어 1단계·2단계 (휴게소·졸음쉼터 안내)

> 게임 응답만으로 졸음을 단정하지 않는 **보조 기능**이다. 화면·음성 어디에도 "졸음운전 감지" 같은 말을 쓰지 않고 "반응이 느려졌어요"라고만 한다.

### 8.1 동작 원리
| 단계 | 언제 | 하는 일 |
|---|---|---|
| 기준값 | 운전자의 평소 응답 시간(문제를 다 듣고 첫 말까지). 기준값이 없으면 첫 5개 답의 중앙값(데모 모드는 1.5초로 시드 — 데모 세션의 기준값은 저장하지 않는다) | 판의 첫 문제·일시정지 직후 답·인식 오류는 빼고 잰다 |
| 느림 | 응답 시간 > max(기준 × 1.5, 기준 + 1.5초) | |
| **1단계** | 최근 5개 중 느림 3개 이상 | 말 걸기 + 난이도 −1 + 카드. 쿨다운 5분(데모 20초) |
| **2단계** | 15분 안에 1단계가 두 번째로 걸림, 또는 (이번 답이 느림 && 최근 5개 정답률 < 50%) | **쉬어 가기 질문 → 경로 위 휴게소·졸음쉼터**. 난이도 −1. 쿨다운 20분(데모 60초) |

2단계에서 쉬어 갈 곳 고르기:
1. **경로 정보가 있으면 경로 위에서만** — 실제 내비 여정은 내비 길 안내 목록(TBT)의 휴게소(`TURN_ENTER_SERVICEAREA`, 이름에 "휴게소"가 있는 것)·졸음쉼터(`TURN_RESTAREA`), 시뮬 여정은 같은 길의 목록. TBT 의 `distance` 는 **앞 항목부터의 구간 거리**라 앞에서부터 더해 "지금부터 거리"를 만든다.
2. 1~80 km 앞에서 **가장 가까운 곳**, 단 휴게소가 가장 가까운 졸음쉼터보다 **5 km 안쪽으로만 더 멀면 휴게소**(화장실·먹거리·수유실 — 가족 여행).
3. 휴게소는 **편의시설**(§8.8)을, 졸음쉼터는 공공데이터 표와 이름으로 맞춘 **좌표**(도착 감지용)를 붙인다. 상·하행은 진행 방향으로 가른다.
4. 경로 정보가 없을 때(길 안내 없음)만 공공데이터 졸음쉼터 253곳 중 진행 방향 앞쪽 — 근사라 노선 이름을 함께 말한다("경부선 부산 방향 오산 졸음쉼터").
5. **경유지는 넣지 않는다** — 경로 위라 내비가 이미 지나가는 곳이다(좌표 경유지는 고속도로 옆 일반 도로에 붙어 우회 경로를 만든다).

도착 = **근처(반경 300 m, 근접 알림·위치)에서 서거나 주차** / 좌표 없는 곳은 **주차** / 시뮬 여정은 **그 지점에 닿으면**. 옆을 지나가기만 하면 도착이 아니다.

### 8.2 시나리오 A — 1단계 [실제 TTS · 대본 답]
1. 패널: 데모 모드 켜짐, 여정 시뮬, 응답 입력 **대본 sleepy**. (이전 시험으로 기준값이 커졌으면 **운전자 기준값 초기화**)
2. 패널 시뮬 경로 **서울 → 부산** → 홈에서 그 줄(현재 경로 자리), **혼자**(운전자 차례만 이어져 빨리 나옴) → 출발 → 기어 **D**.
3. **기대 결과** (11/7 확인: D 뒤 약 50초)
   - 음성 화면 카드 `잠깐 쉬어 갈까요? / 반응이 조금 느려졌어요 · 다음 문제는 쉬운 걸로 갈게요`
   - TTS "아빠, 운전 오래 하셨죠? 다음 문제는 조금 쉬운 걸로 가 볼게요."
   - 점수판 `쉬운 문제 위주로 진행 중`, 패널 `느림 3/5 · 난이도 상한 2 · Stage1 1회`
   - 로그 `Drowsiness: latency=6001ms baseline=1439ms slow=3/5 cap=2` → `Drowsiness: Stage1 → 말 걸기 + 난이도 상한 2`

### 8.3 시나리오 B — 2단계가 저절로 걸림 [실제]
시나리오 A 에서 **대본 sleepy 를 그대로** 둔다.
- **기대 결과** (11/7 확인: 1단계 뒤 약 1분 30초 — 사이에 길 안내 일시정지·판 경계가 끼면 늦어짐)
  - 로그 `Drowsiness: Stage2 (15분 안에 1단계 두 번) → 휴식 권유 + 경로 위 휴게소·졸음쉼터`
  - 이어서 §8.4 의 3~5번과 같은 질문·안내. 쉬어 갈 곳은 그 순간 시뮬 위치 앞쪽의 휴게소·졸음쉼터다(패널 "지금 걸리면 권할 곳" 줄에 미리 보인다).
- 1단계 뒤 30초 넘게 안 나오면 시나리오 C 의 **2단계 시험**으로 바로 볼 수 있다.

### 8.4 시나리오 C — 휴게소 권유 처음부터 끝까지 (시뮬 여정) [실제 TTS·SDK 흐름]
가장 빠르고 확실하게 전체 흐름을 보는 방법(11/7 debug·release 둘 다 확인).
1. 패널: 여정 **시뮬**, 응답 입력 **대본 normal**(대본은 쉬어 가기 질문에 "네"라고 답한다).
2. 패널 시뮬 경로 **서울 → 전주** → 홈에서 그 줄 → 출발 → 기어 **D**. 패널 졸음 케어 칸에 `경로 위: 기흥휴게소 14.8km, 오산졸음쉼터 24.1km, 안성휴게소 41.1km …`, `지금 걸리면 권할 곳: 기흥휴게소 14.8km (경로 위) · 수유실 · 가족사랑 화장실 · 대표 음식 제주고사리육개장`.
3. 첫 문제가 나오면 패널 → **2단계 시험 (다음 운전자 답 뒤)** → Back. 다음 운전자 답 뒤 **질문**:
   - 카드 `잠깐 쉬어 가요 / 반응이 계속 느려졌어요 · 6.1km 앞 기흥휴게소 / 수유실 · 가족사랑 화장실 · 대표 음식 제주고사리육개장` + **쉬어 가기 / 괜찮아요**
   - TTS "아빠, 반응이 계속 느려졌어요. 가는 길에 있는 기흥휴게소가 6킬로미터 앞이에요. 수유실과 가족사랑 화장실이 있어요. 거기서 잠깐 쉬어 갈까요?"
   - 묻는 동안은 시뮬 여정이 멈춘다(30배속이라 대답하기 전에 지나치지 않게).
4. 대본이 1.5초 뒤 "네" → TTS "좋아요. 기흥휴게소에서 쉬어 가요. 도착할 때까지 게임은 쉴게요." →
   - 카드 `기흥휴게소로 가는 중 / 남은 거리 6.2km · 가는 길에 있어요 · 도착하면 알려 드릴게요` + **안내 그만두기**
   - 가운데 `쉬어 갈 곳으로 가는 중이에요 / 충분히 쉬고 이어서 해요 · 계속을 누르면 바로 이어져요`
   - 로그 `rest stop accepted: 휴게소 · 경로 위 · 근접 알림 없음(좌표 없음 — 주차하면 도착)`
5. **도착**: 약 10초 뒤 시뮬 여정이 휴게소에 닿는다 — 로그 `rest stop arrived (시뮬 여정이 쉼 장소에 닿음)`
   - 카드 `기흥휴게소에 도착했어요 / 차를 세우고 충분히 쉬었다 가요 · 다시 출발하면 이어서 해요`
   - TTS "기흥휴게소에 도착했어요. 차를 세우고 충분히 쉬었다 가요." → `쉼터에서 쉬는 중이에요 / 다시 출발하면 이어서 해요 · 바로 하려면 계속` (로그 `RestHold: 쉼터 도착 안내 뒤 다시 출발할 때까지 대기`) — **이 동안 문제를 내지 않는다**
   - 그 전에 기어 **P** 로 세워도 도착(`rest stop arrived (주차)`).
6. **쉬기**: 기어 **P** → 화면 게임 + 맨 위 `기흥휴게소에서 쉬는 중 · 충분히 쉬었다 가요`.
7. **다시 출발**: 기어 **D** → TTS "아빠, 잘 쉬셨나요? 다시 출발해요!" → 응답 창·난이도 초기화(로그 `rested → 다시 출발`, `Drowsiness: 휴식 후 다시 출발 → 응답 창·난이도 초기화`) → 다음 차례.
8. 패널 → **남은 5분으로** → (주행 중이라 짧은 요약 → 기어 **P**) → 요약 `휴게소·졸음쉼터에서 쉬어 가기를 1번 권했어요.`

### 8.5 시나리오 D — 실제 내비 경로 위 졸음쉼터 + 근접 알림 [실제]
에뮬레이터 순정 내비의 TBT 목록으로 고르고, FusedLocation 근접 알림·위치로 도착을 보는 방법(11/7 확인).
1. `adb emu geo fix 127.10 37.40`(판교 부근 — 국내 위치가 있어야 진행 방향·상하행을 안다).
2. 패널 여정 **자동** → 홈 최근 목적지 **부산역**(없으면 순정 내비에서 부산역으로 한 번 길 안내 — §3.2) → 출발 → 순정 내비가 앞으로 나와 경로를 띄움 → 하단 독에서 놀레오로 돌아와 기어 **D**. (11/7 에는 홈 프리셋 서울 → 부산으로 확인했다 — 같은 `requestRoute` 다.)
3. 패널 졸음 케어 칸: `경로 위: 용인졸음쉼터 18.1km, 용인휴게소 28.5km, 덕평휴게소 41.2km, 이천졸음쉼터 48.7km`, `지금 걸리면 권할 곳: 용인졸음쉼터 18.1km (경로 위)` (휴게소가 10 km 더 멀어 졸음쉼터). 로그 `onTBTInfo 54개 · 경로 위 휴게소 9곳 · 졸음쉼터 13곳`.
4. 패널 → **2단계 시험** → Back → TTS "…가는 길에 있는 용인졸음쉼터가 18킬로미터 앞이에요. 거기서 잠깐 쉬어 갈까요?" → 네.
   - 로그 `rest stop accepted: 졸음쉼터 · 경로 위 · 근접 알림 요청`, `proximity alert registered (…)` — 경로 위 졸음쉼터를 공공데이터 표(영동선 강릉 방향 용인)와 맞춰 좌표를 얻었다. 내비 경로는 그대로(경유지·경로 취소 없음).
   - 패널 `쉬어 가기 상태: 가는 중 · 용인졸음쉼터 … (경로 위) · 근접 알림 요청 · 도착 시험 geo fix 127.138727 37.288616`
5. `adb emu geo fix 127.138727 37.288616` → 차가 서 있으므로(에뮬레이터는 D 라도 속도 0 = 정차) 바로 도착 — 로그 `rest stop arrived (위치가 쉼터 0m 안)` 또는 `(근접 알림 ENTER)` → 도착 안내 → 쉬는 중 → P → D → 인사.

### 8.6 시나리오 E — 길 안내가 없을 때 (공공데이터 졸음쉼터 표) [실제 FusedLocation]
내비 경로 정보가 없을 때만 쓰는 근사다. 패널 졸음 케어 칸의 `경로 위: 정보 없음(길 안내 없음 → 표에서 고름)` 과 `표의 앞쪽 졸음쉼터 …` 줄로 본다(게임 없이도 됨). `geo fix` 를 30 m~5 km 떨어진 두 지점에 차례로 넣으면 그 방향으로 움직인 것으로 본다(줄이 안 바뀌면 패널을 닫았다 다시 연다).

| 명령 (순서대로) | 기대 결과 (11/7 확인) |
|---|---|
| `adb emu geo fix 127.03 37.30` → `adb emu geo fix 127.035 37.28` (수원 부근, 남쪽으로) | `위치 방향 168° · 표의 앞쪽 졸음쉼터 오산 졸음쉼터(부산 방향) 14km` |
| `adb emu geo fix 127.09 37.12` → `adb emu geo fix 127.085 37.14` (오산 남쪽, 북쪽으로) | `위치 방향 348° · 표의 앞쪽 졸음쉼터 오산 졸음쉼터(서울 방향) 1km` — 같은 이름의 **반대편 차로** |

이 상태(길 안내 없음)에서 2단계가 걸리면 "경부선 부산 방향 오산 졸음쉼터가 14킬로미터 앞에 있어요. 거기서 잠깐 쉬어 갈까요?"처럼 노선·방향을 함께 말하고, 카드에는 `화면으로만 안내`. **근처 10분** 시뮬 경로와 **목적지 없이**(시간 여정)도 경로 정보가 없어 이 방식이다.

### 8.7 거절·버튼·그만두기
| 하고 싶은 것 | 방법 | 결과 |
|---|---|---|
| 음성 대신 화면으로 답 | 질문 중 **쉬어 가기** / **괜찮아요** | 먼저 온 답(음성 또는 버튼)을 쓴다. 카드가 떠 있는 동안 아래 버튼(일시정지·계속·지금 시작)은 테두리 버튼 |
| 질문 중 멈춤 | 질문하는 중 일시정지(버튼·TBT·Gleo·백그라운드) | 답 없음으로 끝내지 않고, 재개 1초 뒤 다시 묻는다(로그 `쉬어 가기 질문이 끊김 … → 재개 시 다시 묻기`, 11/8 확인). 멈춘 동안 누른 **쉬어 가기**/**괜찮아요** 는 바로 받는다 |
| 가는 중 또 걸림 | 쉼 장소로 가는 중 **계속**으로 게임을 이어 가다 2단계가 다시 걸림 | 다른 곳을 묻지 않고 TTS "아빠, 반응이 계속 느려졌어요. ○○에서 꼭 쉬어 가요." — 카드도 가던 곳 그대로 |
| 거절 | **괜찮아요**(또는 마이크로 "아니요", "괜찮아") | TTS "알겠어요. 대신 다음 문제는 쉬운 걸로 갈게요. 피곤하면 언제든 쉬어 가요." 카드는 15초 남아 있어 그 사이 **쉬어 가기**로 다시 수락 가능 |
| 쉬어 갈 곳이 없음 | 경로 위 1~80 km 안에 없거나, 길 안내 없이 위치·방향을 모를 때 | TTS "…가까운 졸음쉼터나 휴게소에서 잠깐 쉬어 가요." + 카드 **닫기** |
| 가는 중 그만두기 | **안내 그만두기** | 게임 쉬기·도착 감지를 끈다 |
| 쉬는 중 바로 이어 하기 | **계속** | 언제든 바로 이어 간다(가는 중이면 도착 감지는 계속) |

음성 "네/아니요"로 알아듣는 말: 네·예·응·그래·좋아·알겠어·안내해·가자·쉬자·오케이 / 아니·아뇨·괜찮아·싫어·됐어·그냥 가 (부정이 먼저 판정됨).

### 8.8 휴게소 편의시설
- 자료: 한국도로공사 휴게소별 편의시설(수유실·수면실·샤워실…·대표 음식)과 가족사랑 화장실 운영 여부 — 247곳(`assets/content/service_areas.json`, 출처는 [`CONTENT_SOURCES.md`](CONTENT_SOURCES.md)).
- 말하는 것: 수면실(졸음) → 수유실 → 가족사랑 화장실 중 있는 것 2개까지. 화면에는 대표 음식까지.
- TBT 의 휴게소 이름과 **정확히 같은** 이름만 맞춘다(천안/천안삼거리처럼 앞부분만 같은 다른 휴게소를 붙이지 않으려고). 민자 고속도로 휴게소(정안알밤·탄천·경기광주·강릉대관령 등)는 자료에 없어 이름만 말한다.
- 상·하행은 진행 방향으로 고른다(예: 안성휴게소 부산 방향 = 수유실·샤워실·세탁실 / 서울 방향 = 수유실·약국). 방향을 모르면 양쪽에 공통인 시설만.

### 8.9 알아 둘 한계
- 실제 내비에서 권한 곳을 서지 않고 지나치면 게임은 계속 쉬고 있다 → **계속**·**안내 그만두기**로 이어 간다(자동 재권유는 아직 없음). "지나가기만 하면 도착이 아님" 규칙은 에뮬레이터 차가 움직이지 않아 실제로는 확인하지 못했다(코드 규칙).
- 실차에서 주행 중 TBT 를 얼마나 자주 보내는지 미확인 — 그 사이는 남은 거리가 준 만큼 앞당겨 계산한다. 에뮬레이터 TBT 목록은 50여 항목이라 아주 긴 경로의 뒷부분은 빠질 수 있다(가까운 곳만 쓰므로 문제없음).
- 휴게소는 좌표가 없어 근접 알림을 쓰지 못한다(주차하면 도착).
- 근접 알림은 요청마다 번호를 붙여, 취소·도착·다른 쉼 장소로 바뀐 뒤 늦게 온 등록·ENTER 는 무시하고 늦게 온 알림은 바로 지운다(로그 `proximity alert registered late (…) → removed`, `ENTER from an old proximity alert → ignored`).
- 길 안내가 없을 때의 표는 어느 고속도로를 달리는지 모르는 근사다. 원자료의 방향 표기("A기점 + B종점")를 A → B 차로로 해석했다(공식 정의 미확인).

## 9. 도착·요약, 게임 끝내기, 이어서 하기

### 9.1 도착 요약 [실제]+[시뮬]
- **확인**: 패널 → **남은 5분으로**(시뮬·시간 여정) 또는 실제 내비 도착.
- 목적지 없이 논 세션은 제목이 `도착했어요` 대신 `시간이 다 됐어요`, 그 아래 `목적지 없이 30분`(11/8 확인).
- **주행 중**(주행 규제 `requiresDO`)에는 스크롤 없이 한 화면: `도착했어요` · `N번 맞혔어요 · 1등 ○○` · `차를 세우면 오늘의 기록을 모두 보여 드려요` · **처음으로**. 정차하면(기어 P) 아래 전체 요약으로 바뀐다(11/8 확인 — Virtual Console 기어 D/P).
- **기대 결과**(정차 중): "곧 도착이에요. 이번 판은 여기까지 할게요!" → `도착했어요` + 목적지 이름 — `오늘의 기록` 카드(크게 `N 번 맞혔어요`, `오늘의 1등: ○○`, `함께한 게임`, `끝말잇기 최장 N개 낱말`)와 `가족 점수` 카드(순위·아바타·점수·정답 수)가 넓은 창에서는 같은 높이로 나란히, `지나온 지역` 칩, `가는 길에 쉬운 문제로 N번 바꿔 드렸어요. 휴게소·졸음쉼터에서 쉬어 가기를 N번 권했어요. 장거리 운전, 수고 많으셨어요.` → **처음으로**.

### 9.2 게임 끝내기
- 음성 화면: 일시정지·쉬는 시간·출발 대기·모든 판 완료 때 **게임 끝내기**(문제를 내고 듣는 동안에는 일시정지 버튼 1개만). 화면 게임: 게임 목록의 머리 줄(게임을 연 동안에는 **← 목록**으로 돌아가서).
- 맞힌 문제나 마친 판이 있으면 `여기까지 했어요` 요약, 없으면 바로 홈. 내비 길 안내는 취소하지 않는다.

### 9.3 이어서 하기 (상태 복원)
- **확인**: 게임 중 다른 앱(하단 독의 내비 등)을 열어 놀레오를 뒤로 보내 상태를 저장하게 한 뒤 `adb shell am force-stop com.nolleo.app` → 다시 실행. Pleos 런처에서는 홈 키를 눌러도 놀레오 창이 그대로 보여 뒤로 가지 않고(저장하지 않음), `am kill` 은 프로세스를 끝내지 않았다(11/8 관측).
- **기대 결과**: 홈 맨 위 `진행 중이던 여정이 있어요 / ○○ · N번째 판` + **이어서 하기 / 새로 시작**. 11/8 목적지 없이 30분으로 확인: `목적지 없이 30분 · 1번째 판` → 이어서 하기 → 로그 `timer trip 30분 (x1.0)`, `session restored at round 1` → 화면 칩 `남은 시간 30분`(주차 중이라 그대로).
- 이어서 하는 것(저장본 v3, 11/8): 점수·판·차례, 졸음 지표(응답 창·난이도 상한·1단계 시각·2단계 횟수와 쿨다운), 끝말잇기 이력과 최장 기록, 운전자, **시뮬·시간 여정의 남은 시간**(꺼져 있던 동안은 흐르지 않은 것으로 봄), 시간 여정의 전체 시간과 "목적지 없이" 여부. 실제 내비 여정(현재 경로·최근 목적지)은 내비에 남은 길 안내의 남은 시간을 쓴다.
- 이어 가지 않는 것: 쉬어 가기 진행(가는 중·쉬는 중)은 처음 상태로 시작한다(11/8 결정). 정차 중 화면 게임 점수도 새로 시작.
- 예전(v1·v2) 저장본도 읽는다(새 항목은 기본값). 모르는 버전·말이 안 되는 저장본은 버리고 홈으로.
- 작업 제거 뒤 같은 프로세스에서 다시 열어도 진행 중이던 세션은 메모리에서 정리되고 **이어서 하기**로 고를 수 있다.

## 10. 창 배치·Back 키·백그라운드 [실제]
- **3분할**: 놀레오가 앱 영역 전체일 때 화면 오른쪽 끝 **⋮** 창 막대를 가운데로 끈다 → 놀레오가 왼쪽 창으로 줄어든 직후 스스로 맨 오른쪽(조수석 쪽)으로 옮겨 `Driving view | 내비 | 놀레오`. 자리를 바꾸려고 놀레오가 기본 지도 앱을 앞으로 불러온다. 가운데 막대를 탭해 직접 바꾼 자리는 그대로 둔다(로그 `Window: 3분할 …`). 좁은 창에서도 잘리지 않는다(세로 1창은 §13).
- **Back 키**: 맨 위 화면에서는 앱을 끝내지 않고 뒤로 보낸다(`moveTaskToBack`). 다시 열면 그대로.
- **백그라운드**: 다른 앱이 놀레오 창을 덮으면 즉시 멈추고(포커스 반납·상태 저장), 돌아오면 `잠시 멈췄어요` + **계속** → 같은 문제부터. 최근 목적지로 출발(경로 요청)할 때 순정 내비가 앞으로 나오는 것도 이 경우인데, 이때는 길 안내가 시작되면 놀레오가 스스로 다시 앞으로 온다(§3.2 — 말하던 중이 아니었으므로 바로 이어짐).
- **3분할을 앱이 만들 수는 없다**(11/8 시험): 세로를 요청하면 창이 나뉘지 않고 양옆에 검은 띠(레터박스 — 플랫폼 금지)만 생기고, 내비를 왼쪽 절반 크기로 띄우라고 해도(launch bounds) 앱 영역 전체를 덮는다. 3분할은 사용자가 창 막대로 만든다.

## 13. 에뮬레이터에서 확인할 수 없는 것
- 차가 움직이지 않음: 실제 내비 여정의 남은 시간 감소, 주행 중 TBT 갱신, 쉼 장소를 지나쳐 가는 경우 → 시뮬 여정·`geo fix` 로 대신 확인.
- 통화·Gleo·다른 미디어 앱으로 인한 오디오 포커스 손실(§6.2, 화면 게임 읽기 중단 §7, 정차 끝말잇기 멈춤 §7.3).
- 정차 끝말잇기를 실제 마이크(호스트 오디오 입력)로 끝까지 해 보지는 않았다 — 대본 응답과 무응답으로 확인(§7.3).
- 음성 엔진 회복: 초기화 실패·STT 치명 오류(MIC_ERROR 등) 뒤 다음 출발·앱 복귀 때 다시 초기화하는 경로 — 에뮬레이터에서 실패를 만들지 못했다.
- 실제 내비 여정에서만 생기는 것: 앱보다 먼저 시작한 길 안내의 상태 채우기(§3.2), 정체로 남은 시간이 크게 바뀔 때 다시 짠 판 기다리기(§3.1), 경로 위 쉼 장소 거리의 기준(TBT 를 받으면 남은 거리를 바로 다시 조회).
- 실차 내비의 최근 목적지·예상 시간(`requestTrip`) 응답, 그리고 최근 목적지로 출발했는데 내비가 길 안내를 시작하지 못해 예상 시간으로 대신 세는 경로(§3.2) — 에뮬레이터 내비는 늘 길 안내를 시작했다.
- 출발 뒤 놀레오가 다시 앞으로 오는 것(§3.2)은 에뮬레이터에서만 확인했다. 시스템은 "Background activity launch blocked" 로그를 남기면서도 이미 있는 놀레오 창을 앞으로 보였다 — 실차 Android 빌드가 더 엄격하면 돌아오지 않을 수 있다(그때는 내비가 앞에 남음, 크래시 없음).
- 세로 1창에서의 화면 게임 배치: `wm size` 로 바꾸면 Pleos 화면 자체가 다시 배치되지 않아 확인하지 못했다(좁은 창은 위아래 배치 + 스크롤로 구현). 3분할의 좁은 창(약 840px)에서 홈·화면 게임(목록·세 게임)·요약·음성 화면은 11/7~8 확인.
- 실제 좌석 착좌(§3.3).
- 실차의 주간/야간 전환: 에뮬레이터에서는 `cmd uimode night` 로만 바꿔 봤다. 실차가 같은 시스템 야간 모드 신호로 바꾸는지는 확인 못 함.
- 주행 규제 비트 개별 시험(`driving_regulation` 셸 명령이 이 빌드에 없음) — 기어 D 의 `NO_VIDEO+NO_SETUP`(80)만 확인. `LIMIT_STRING_LENGTH`(문제를 1줄로)는 코드만.
- Android TTS 폴백(에뮬레이터에 한국어 엔진 없음), 실제 Suspend(IGN OFF).

## 14. 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 패널 졸음 케어 칸 `위치 모름` | 국내 위치가 없다. 시뮬 여정을 시작하거나 `geo fix`(§0.3). 위치 권한 허용 여부(§0.1) |
| `경로 위: 정보 없음` | 길 안내가 없다(또는 내비가 경로를 다시 잡는 중). 시뮬 여정은 부산·강릉·전주 시뮬 경로에 경로 목록이 있고, 근처 10분·목적지 없이(시간 여정)는 없다 |
| `지금 걸리면 권할 곳: 없음` | 경로 위 1~80 km 안에 휴게소·졸음쉼터가 없다(도착 직전 등), 또는 길 안내 없이 위치·방향을 모른다 |
| 1단계가 안 나온다 | 응답 입력이 **대본 sleepy** 인지(체크 ✓ 확인), 동승자가 있으면 차례가 늦게 옴(**혼자** 추천), 이전 시험으로 기준값이 커졌으면 **운전자 기준값 초기화**(세션 중에 눌러도 다음 답부터 다시 기준을 만든다). 판 첫 문제·일시정지 직후 답·인식 오류는 계산에서 뺀다 |
| 요약이 한 줄뿐이다 | 주행 중(주행 규제)이라 짧게 보인다. 기어 P 로 세우면 전체 기록 |
| 출발을 눌러도 `곧 도착이라 게임을 시작하지 않아요` | 남은 시간이 5분 이하(현재 경로·최근 목적지가 거의 다 옴). 다른 목적지나 `목적지 없이`를 고른다 |
| 홈에 최근 목적지가 없다 | 길 안내 중이면 숨긴다(현재 경로만). 패널 여정이 **시뮬**이면 숨긴다. 내비에 최근 목적지가 없으면(새 에뮬레이터) 순정 내비에서 한 번 길 안내를 한다 |
| 최근 목적지 오른쪽이 계속 `시간 확인 중` | 내비가 `requestTrip` 에 답하지 않았다(로그 `requestTrip: 5초 안에 onTripInfo 없음`). 앱을 뒤로 보냈다가 다시 열면 다시 묻는다. 그동안은 그 줄로 출발할 수 없다 |
| 2단계 시험 버튼이 회색 | 게임(세션)이 없을 때. 출발 후 누른다. 누른 뒤 **다음 운전자 답** 뒤에 걸린다 |
| `geo fix` 를 해도 도착하지 않는다 | 경도가 먼저인지, 패널 "쉬어 가기 상태"의 좌표와 같은지, 상태가 `가는 중`인지, 차가 서 있는지(주행 중 속도가 있으면 지나가는 것으로 봄). 좌표가 없는 휴게소는 기어 P 로 도착 |
| 내비가 앞으로 나와 놀레오가 안 보인다 | 최근 목적지로 출발하면 순정 내비가 앞으로 나오는 것이 정상이고, 길 안내가 시작되면(에뮬레이터 약 7초) 놀레오가 스스로 돌아온다. 30초 안에 길 안내가 시작되지 않았거나 플랫폼이 막으면 하단 독의 놀레오 아이콘 → (말하던 중이었으면) **계속** |
| 출발하자마자 요약 화면 | 최근 목적지의 출발 전 예상 시간과 달리 실제 길 안내가 5분 이하였던 경우 → 정상(남은 5분에 결과를 정리한다). 예상 시간이 5분 이하면 처음부터 출발을 막는다 |
| 소리가 안 들린다 | 에뮬레이터·호스트 볼륨, 패널 음성 칸 `Pleos(ON_DEVICE) TTS 사용 가능` 인지 |
| 화면 게임이 다음 문제로 안 넘어간다 | 상태 줄이 `소리가 멈췄어요`면 포커스를 못 얻었거나 잃은 것 — 저절로 이어 가지 않으므로 **다음 문제**/**다시 듣기**. 패널 음성 엔진이 **대본**이면 소리 없이 글자 수만큼 기다린 뒤 넘어간다 |
| 정차 끝말잇기가 멈춰 있다 | 카드가 `잠깐 멈췄어요`·`소리가 멈췄어요`면 다른 앱이 덮었다 돌아왔거나 포커스를 잃은 것 — **이어서 하기**(목록에서 다시 열면 저절로 이어짐). `대답이 없어서 멈췄어요`면 잇달아 대답이 없던 것 — 패널 응답 입력·에뮬레이터 마이크 설정(§5.3)을 확인하고 **다시 하기** |
| 마이크로 답해도 무응답 | 에뮬레이터 Microphone 설정(§5.3), 패널 응답 입력이 **마이크**인지 |
| 홈에 늘 `좌석 센서가 동승자 3명을 감지했어요` | 에뮬레이터 SDK 값이 동승석 4곳 착좌로 고정돼 있다(§3.3). 앱 고장이 아님 — 무시하거나 **3명으로**를 눌러 보여 준다 |
| 하단 독 아이콘이 차콜 바탕의 노란 언덕 길 그림이 아니다 | 다른 패키지의 예전 빌드가 남아 있으면 지우고 새 APK 를 설치한다. 그래도 그대로면 런처 캐시 — 야간/주간 전환이나 재부팅 뒤 바뀐다 |
