# 2차(12/3 오프라인 PT) 설계 메모

아직 구현하지 않은 2차 작업 후보와 설계 메모만 모은다. 구현이 끝난 항목은 이 파일에서 지우고, 동작은 [`FEATURE_GUIDE.md`](FEATURE_GUIDE.md), 작업 기록은 [`WORK_STATUS.md`](WORK_STATUS.md)에 남긴다. 반쯤 만든 기능은 데모에서 사고만 내므로 1차 제출본에는 넣지 않는다. 코드의 확장 지점은 `TODO(phase2)`로 표시했다(지금은 `core/navi/NaviHelperTripSource.kt` 3곳, 아래 §3).

## 1. 쉬어 가기(졸음 케어 2단계) 후속
졸음 케어 1·2단계와 경로 위 휴게소·졸음쉼터 안내는 구현을 마쳤다(동작: FEATURE_GUIDE §8, 기록: WORK_STATUS 1.10·1.11). 남은 것:
- **실차 검증**:
  - 주행 중 내비가 `onTBTInfo`를 얼마나 자주 보내는지(그 사이는 남은 거리 변화로 앞당김)
  - 고속 주행에서 근접 알림 ENTER가 제때 오는지
  - 근처를 지나가기만 할 때 도착으로 치지 않는지
- **권한 곳을 지나쳤을 때**: 지금은 게임이 계속 쉬고 "계속"으로 이어 간다. "지나쳤어요, 다음 휴게소에서 쉬어 가요"처럼 다시 권할지 검토한다.
- **휴게소 좌표**: 도로공사 OpenAPI(인증키)로 빌드할 때 받아 넣으면, 휴게소도 근접 알림으로 도착을 알 수 있다. 앱 실행 중에는 여전히 네트워크를 쓰지 않는다.
- 졸음쉼터 원자료의 방향 표기("A기점 + B종점")를 A → B 차로로 읽은 해석이 맞는지 확인한다(한국도로공사 문의 또는 실측).
- 길 안내가 없을 때의 표 근사 보완: NaviHelper `onCurrentLocationInfo`의 `heading`을 진행 방향 후보에 넣는다.
- 실차 내비의 휴게소 이름을 모아 편의시설 자료 이름과 맞추기. 지금은 이름이 정확히 같을 때만 붙인다(예: 자료의 "하남만남의광장").

## 2. 지역 스탬프 영속화
- 지금은 지나온 지역(`regionsVisited`)을 세션 안에서만 모아 요약 화면에 칩으로 보여 준다(FEATURE_GUIDE §9.1).
- 2차: 지역 퀴즈를 맞힐 때 `stamps(regionCode, firstAt, count)`를 DataStore(또는 JSON 파일)에 쌓는다.
  - 홈에 "스탬프 17칸" 진행도를 보여 준다.
  - 새 지역의 첫 스탬프는 TTS로 축하한다.

## 3. 구간별 자동 일시정지 고도화
지금의 TBT 자동 일시정지는 FEATURE_GUIDE §6.1에 있다. 추가할 신호는 `core/navi/NaviHelperTripSource.kt`의 `TODO(phase2)` 콜백 자리에 넣는다.
- `onRouteStateInfo.trafficStatus`: `TrafficCongestionType.HEAVY` 구간에 들어서면 문제 간격을 늘리고 긴 문제를 피한다(멈추기보다 "천천히").
- `onCautionPointInfo`: 급커브·사고다발 구간에 가까워지면 일시정지한다.
- `onCameraAlert`: 단속 카메라 안내 직전에 일시정지한다(내비 음성과 겹치지 않게).
- 오디오 포커스: 내비 안내 음성(NAVIGATION 컨텍스트)과의 상호작용을 Interaction Matrix로 검증한다.

## 4. 이동 앨범
- 도착 요약 화면을 확장한다: 경로(시뮬 타임라인 또는 FusedLocation 샘플링 좌표) 위에 판·정답·지역 스탬프를 시간순으로 놓는다.
- 지도는 순정 내비 화면을 쓰지 않고, 앱 안의 간단한 경로선 + 지역 칩으로 그린다(외부 지도 SDK·네트워크 없이).
- `NaviHelper.requestNavigationScreen(OverviewRoute)`는 `NAVI_CUSTOM_MAP` 퍼미션이 필요하다. 쓸지는 App Market과 협의한 뒤 정한다.

## 5. 정차 중 화면 게임 더하기와 후속
지금의 화면 게임 3종(사자성어·지역 퀴즈·끝말잇기)은 FEATURE_GUIDE §7에 있다. 아래 둘은 "준비 중" 카드 자리만 있다. 둘 다 SCREEN 모드에서만 열리고 출발하면 바로 닫힌다. 소리를 낸다면 다른 화면 게임과 같은 규칙(`app/ScreenQuizController.kt`)을 따른다.
- **틀린 그림 찾기**: 같은 벡터 그림 두 장에서 다른 곳 3~5개를 터치한다. 사진이나 외부 그림 없이 앱이 그린 장면(차·길·집)을 바꿔 만들면 저작권 걱정이 없다. 쓸 그림을 먼저 준비해야 한다.
- **노래방**: 정차 중에만 연다. 가사를 화면에 띄우고 반주는 미디어 포커스(`USAGE_MEDIA`)로 튼다.
  - 저작권 있는 곡은 쓸 수 없으므로 동요·공유 저작물로 시작한다.
  - 주행 중에는 열지 않는다(영상·자동 스크롤 금지 규칙).

화면 게임 후속 후보:
- **사자성어**:
  - 한자 급수(`chars[].grade`)로 난이도 고르기
  - 틀린 사자성어 다시 내기(오답 노트)
  - 음성 판에 "뜻 듣고 사자성어 말하기" 넣기(STT가 4글자 한자어를 잘 받는지 먼저 확인)
  - 앱 안에 자료 출처·라이선스(CC BY-SA 4.0) 표기(WORK_STATUS §2.1 5번)
- **지역 퀴즈(정차)**: 오답 보기를 사람이 고른 목록으로 바꾸기. 지금은 같은 갈래 다른 문항의 정답을 쓴다.
- **끝말잇기(정차)**: "보기 고르기" 대신 말로 잇는 판(STT)도 고를 수 있게 하기.
- 정차 게임 점수를 요약 화면에 넣을지 정하기. 지금은 게임마다 세션 동안만 유지한다.

## 6. Gleo Interface (`assets/schema.json`) — 파일은 아직 넣지 않음
1차에 파일을 넣으면 심사 변수가 늘어나므로 문서로만 남긴다. 2차 후보 함수(영어 description, 3개 이하):

| 함수 | 설명(영문) | 앱 동작 |
|---|---|---|
| `START_GAME` | Start a family voice game on the current trip | 홈 설정이 있으면 세션 시작, 진행 중이면 다음 판 시작 |
| `PAUSE_GAME` | Pause or resume the current voice game | `PauseReason.USER` 토글 |
| `SKIP_QUESTION` | Skip the current question | 현재 차례를 무응답 없이 넘김(졸음 지표 제외) |

- intent-filter를 두고, 7초 안에 `APP_ACTION_RESPONSE` 브로드캐스트를 보낸다(DEV_GUIDE §9).

## 7. 그 밖의 2차 작업 후보
- **홈 목적지 후속** (11/8 홈을 현재 경로 · 내비 최근 목적지 · 목적지 없이로 바꾼 뒤 — FEATURE_GUIDE §3.2):
  - 집·회사 즐겨찾기: `NaviHelper.getBookmarkInfo` → `onBookmarkInfo`(`BookmarkType.HOME/OFFICE`)로 등록된 것만 최근 목적지 앞에 넣는다. 퍼미션은 `NAVI_ROUTE` 그대로. 에뮬레이터는 집·회사가 등록돼 있지 않아(빈 이름·0 좌표) 1차에 넣지 않았다.
  - 실차 내비가 `requestTrip` 에 답하지 않으면 최근 목적지가 `시간 확인 중`으로 남아 그 줄로 출발할 수 없다. 지금 위치(FusedLocation)와의 직선거리로 대략의 시간을 셈하는 대안을 실차 확인 뒤 정한다.
  - 목적지 없이: 지금은 다른 여정처럼 남은 5분에 결과를 정리한다(30분이면 약 25분 논다). 정한 시간을 끝까지 쓰게 할지 정한다.
- **Vehicle SDK 리스너를 화면이 보일 때만 등록**: 샘플 README("관찰하는 화면이 멈추면 unregister")와 DEV_GUIDE §5.4 기준이다. 지금은 브레이크·좌석 리스너가 앱 수명 동안 등록돼 있다(좌석은 홈에서만 쓴다).
- 운전자 프로필 확장: 이름 직접 입력은 정차 중에만 받고, 좌석 착좌·운전석 프로필과 연동한다.
- 동승자 이름 커스터마이즈, 아이 연령대별 난이도.
  - 이름을 바꾸면 이름 첫 글자 아바타도 따라 바뀐다.
  - 가족마다 아바타 색을 주는 것은 "강조색 하나" 원칙과 부딪히므로, 글자·모양으로 구분하는 쪽을 먼저 검토한다.
- 디자인 후속:
  - 실차의 주간/야간 전환 신호가 시스템 야간 모드(`UI_MODE_NIGHT`)로 오는지 확인한다.
  - Pleos 디자인 에셋(Figma)의 시스템 색 토큰과 우리 팔레트를 대조한다.
- 서버 TTS/STT(HYBRID) 품질 비교: `local.properties`에 Client ID/Secret만 넣으면 전환된다.
- 앱 안에서 버전을 확인해 `market://detail?package=com.nolleo.app`로 안내한다(DEV_GUIDE §11.2).

## 8. 구조 리팩토링 후보 (2차 PT 뒤 다시 판단)
11/8 검토 문서(로컬 `.cache/REFACTORING_REVIEW.md`, 저장소에는 없음)에서 **하지 않기로 한** 큰 재구성이다. 결함은 1.21(WORK_STATUS)에서 작게 고쳤고, 아래는 사용자에게 보이는 이득 없이 시연 흐름 전체를 건드려 미뤘다. 2차 기능을 넣으며 그 영역이 커질 때 다시 본다.
- `GameCoordinator`·`AppContainer` 분해 — 홈·시작·저장·포커스·TBT·휴식·설정·디버그를 한 곳이 조정하고, 화면·컨트롤러가 컨테이너 전체를 받는다. 그래서 Coordinator·컨트롤러는 단위 테스트가 없다(판단 부분만 작은 함수로 빼서 시험 중).
- `GameSession` 분해(차례 실행 `TurnRunner` 와 세션 진행 나누기).
- 세션 상태 기계(Idle/Starting/Running/Stopping)·구독 소유권 재배치, 음성 요청의 `Completed/Cancelled/Failed` 결과 타입(서버 TTS/STT 를 붙일 때), 쉬어 가기 상태 기계를 순수 로직/효과로 나누기, 길 안내 일시정지 정책 추출(구간별 신호 §3 과 함께), 화면 `UiState`/presenter, 위치 입력 타입·저장소 인터페이스, 사전 로딩 상태 기계(사전을 내려받게 바뀔 때), 게임별 타입 저장 모델(화면 게임 복원 등 저장 범위가 커질 때).
- 문구를 `strings.xml` 로 옮기기(다국어를 할 때), 디버그 패널을 디자인 규칙에 맞추기(사용자 기능으로 바꿀 때).
